SlopOS Driver-Framework BASE — Bus Model & Hotplug

The remaining foundations of the driver framework: a unified Bus trait that lets platform/ACPI devices bind as declaratively as PCI devices do, and the deferred-probe / hotplug / unbind substrate that makes drivers restartable and hardware removable. Builds directly on the in-tree registry (match-tables, binding/claim, devres, the scanout arbiter, driver_core::msi). GPU internals (GGTT, forcewake, mode programming) are out of scope.

1. Purpose & Scope

In scope: the unified Bus trait and generic probe_bus<B> matchmaker; a gated .platform_registry + platform_driver! for ACPI-matched devices; generalising BoundDevice over the bus; the retry-to-fixpoint deferred-probe queue; unbind (remove); hot-add/rescan including GPU→GPU scanout re-claim; further buses (USB, PCIe hotplug); and the opportunistic virtio→DmaCoherent migration once a real VT-d mapper exists.

Out of scope: GPU driver internals, and any rework of the existing PCI registry machinery — this plan consumes it (Section 3) rather than changing its semantics.

2. Principles & Constraints

Every design decision below is bounded by SlopOS's framekernel discipline. These are not guidelines — they are CI-enforced invariants the implementation must satisfy.

  • Unsafe only in slopos-ostd. The driver crate is #![forbid(unsafe_code)]. Every new primitive a driver touches — the Bus trait, the generic matchmaker, the platform registry — is pure-safe Rust over ostd primitives. scripts/check_unsafe_outside_ostd.sh stays green.
  • 2 KiB per-function stack-frame gate. Probe loops must never copy a device array onto a frame; devices are fetched one at a time through single-element accessors (the pci_device_at idiom). Owned binding state is built off-stack via KBox::try_init(T::init_…()). scripts/check_stack_sizes.sh is re-run on builddir/kernel.elf after each phase.
  • Soft-float. Matching, binding, and arbitration are integer/pointer math and fn-pointer dispatch — zero XMM/YMM. scripts/check_kernel_softfloat.sh is unaffected.
  • Link-section registration is sacred. .driver_registry (link.ld:74-78) stays; entries grow fields but remain #[repr(C)] rodata. Adding a driver stays purely additive — no central list, no init-order dependency, no global mutable vector. The platform registry mirrors this with its own section, never merged.
  • No heap alloc under an IRQ-off cli-lock. The buddy allocator's LUF reuse path does a hidden cross-CPU TLB drain; allocating under a held cli-lock risks the slab-across-LUF-drain deadlock. Probe (and its heap-allocating attach) always runs with neither the enum lock nor the claim lock held — the generic matchmaker must preserve this.
  • QEMU-testability via virtio. The Bus machinery, claim table, and deferred queue are exercisable under just test on q35 with virtio-blk/net/gpu plus the synthetic-driver matchmaker tests. PS/2 is QEMU-testable; the I2C-HID touchpad is HW-only. Test-only dummy drivers register through the cfg(tests=on) side-table so they never land in a shipped .driver_registry.

4. Target Base Architecture

Two layers. The ostd trust domain owns all unsafe and exposes the safe device-model primitives; the driver crate declares tables and writes typed probes, reaching hardware only through the capability handle. The Bus trait unifies PCI and platform/ACPI at the concept level — link sections stay separate, and no crate dependency edge inverts.

 |  slopos-drivers  (#![forbid(unsafe_code)])                                 |
 |   pci_driver! / platform_driver!  { match_table, priority, probe }         |

The payoff this architecture protects: a complete PCI driver today is one file plus one pub mod line — a match_table, a priority, and a lock-free probe that vends resources through BoundDevice and returns Bound/Declined. Phase 1 makes that same template work for a platform/ACPI device; Phase 2 makes it survive unbind and hotplug.

Phase 1 — Unified Bus/Device Model (PCI + gated Platform/ACPI) BUILD

Effort: XL Risk: Med Gate: a concrete second platform device (GPIO/SPI/USB or a deferred-probe parent-bus edge)

Goal

Unify PCI and an ACPI-matched platform_driver! at the concept level under one Bus trait — without merging link sections or inverting any crate dependency edge. One generic probe_bus<B> matchmaker (grown out of the existing factored matchmake/ClaimSink core) drives both. This makes the one-file driver template bus-agnostic.

What it unblocks

Declarative platform/ACPI device binding; removal of hand-wired boot steps for device drivers (the priority-82 touchpad); scaling to many platform devices. Gated on a concrete second consumer — until then the explicit-priority boot_init! mechanism already handles the actual device count (deliberate YAGNI line).

Tasks

  • BUILD Bus trait (associated Device/MatchKey/DriverEntry + NAME/drivers/device_count/matches/priority/probe). Reconcile its shape with the in-tree probe contract (&mut BoundDevice, ProbeOutcome, PciProbeError) and the ClaimSink seam at implementation time — the trait must be a generalisation of the shipped matchmaker, not a parallel one.
  • BUILD generic probe_bus<B> + per-(bus,idx) ClaimTable + priority_order — the PCI-specific loop becomes the first instance.
  • BUILD generalise BoundDevice over the bus (BoundDevice<B> or a per-bus device-info associated type) so platform probes vend MMIO/IRQ/DMA through the same devres bag.
  • REFINE impl Bus for PciBus over the existing PciDriverEntry/PciMatch; route pci_probe_drivers through probe_bus::<PciBus> with zero behavioural change (the binding tests in drivers/src/tests/pci_binding.rs are the regression guard).
  • FUTURE add a gated .platform_registry section to link.ld mirroring .driver_registry (74-78) with its own __start_/__stop_ brackets; PlatformDriverEntry + AcpiId + impl Bus for PlatformBus matched on _HID/_CID via the existing focused DSDT/AML walker in slopos-acpi; a cfg(tests=on) side-table mirroring the PCI one.
  • FUTURE migrate the PS/2 / I2C-HID touchpad off the priority-82 boot_init! step onto deferred-probe; keep boot_init! for the ~12 true platform steps.

API sketch

// the unifying abstraction (pure-safe glue)
pub trait Bus: 'static {
    type Device: Copy + 'static;        // e.g. PciDeviceInfo
    type MatchKey: 'static;             // e.g. PciMatch (const-constructible)
    type DriverEntry: 'static;          // e.g. PciDriverEntry (#[repr(C)] link-section static)
    const NAME: &'static str;           // "pci" / "platform"
    fn drivers() -> &'static [Self::DriverEntry];
    fn device_count() -> usize;                              // index-by-usize; NEVER copy the array
    fn device_at(idx: usize) -> Option<Self::Device>;        // single-element copy, lock released
    fn matches(e: &Self::DriverEntry, d: &Self::Device) -> bool;   // pure data (+ fallback)
    fn priority(e: &Self::DriverEntry) -> u8;
    fn probe(e: &Self::DriverEntry, dev: &mut BoundDevice<Self>)
        -> Result<ProbeOutcome, ProbeError>;
}

Framekernel notes

  • The Bus trait, probe_bus, and the macros are pure-safe glue; all unsafe lives in the ostd primitives BoundDevice wraps (MmioRegion, IrqAllocator::alloc, DmaCoherent::alloc).
  • Link sections stay separate (not merged) so each bus carries its own #[repr(C)] entry type without a tagged union.
  • Lock discipline carries over verbatim: enum lock and claim lock single-purpose, never nested, probe lock-free. A regression that re-locks the enum lock inside probe deadlocks (non-reentrant SpinLock).
  • DCE note: #[used] defeats intra-crate DCE but does NOT force an rlib member to link; a future per-subsystem crate split needs KEEP + -u<sym>/--whole-archive per driver archive (the Asterinas/RfL idiom).

Testability Partial

The machinery (Bus trait, probe_bus, ClaimTable) is fully QEMU-testable: the existing synthetic-driver matchmaker tests generalise, and the virtio path live-verifies PCI-through-the-generic-loop. PS/2 is QEMU-testable; the I2C-HID touchpad is HW-only. ACPI matching depends on the focused DSDT/AML walker correctly surfacing _HID/_CID.

Risks

  • Routing PCI through the generic loop must be behaviour-preserving — the binding tests (ordering/dedup, dup-claim, specific-beats-generic, deferred-then-bound) plus the full just test suite are the guard.
  • ACPI matching depends on slopos-acpi's focused DSDT/AML walker; the touchpad deferred-probe parent-bus edge must actually resolve or the touchpad never binds.
  • Cross-crate split risk (if ever pursued): a per-subsystem rlib nobody names is silently DCE-dropped → driver disabled with NO error; requires -u/--whole-archive force-link.

Phase 2 — Deferred-Probe Queue, Hotplug, Unbind, More Buses FUTURE

Effort: XL Risk: Low now (additive on the Section-3 foundations)

Goal & tasks

Additive by design: binding, devres, the arbiter's two-phase API, and the Deferred outcome are the prerequisites, and they exist. Each item lands independently.

  • FUTURE Retry-to-fixpoint deferred-probe queue (the bounded N=1 pass generalises; the (drv_i, dev_idx) worklist shape is already forward-compatible). Must carry a per-(driver,device) retry cap: IoMem has no Drop, so each failed attempt that mapped a BAR leaks one BAR-VA window — the cap is the leak bound until recyclable VA exists. Prefer map_bar after the steps most likely to defer.
  • FUTURE remove on the binding (the claim slot already stores Binding above Devres, so driver-quiesce-then-resource-release drop order is structural). Move any remaining driver device-state into the slot so unbind owns the full teardown (virtio device-state currently lives outside it).
  • FUTURE Hot-add/rescan + mid-session GPU→GPU scanout re-claim: add a quiesce fn-pointer to ScanoutProvider + compositor-park coordination (the two-phase claim/commit API makes this additive). Rescans run post-SMP-online, so probe_bus's SMP-reentrant lock discipline (never-nested claim locks) becomes load-bearing here, not at first boot. Design-review-gated: COMPOSITOR_FB_ACQUIRED assumes one scanout for the compositor's lifetime — a GPU→GPU takeover has a present-goes-nowhere window that needs an explicit protocol.
  • FUTURE USB / PCIe-hotplug buses via the same Bus trait (the xHCI stack has its own plan: plans/usb-xhci.md).
  • FUTURE Opportunistic virtio→DmaCoherent migration if/when a real VT-d mapper justifies the churn (the identity-mapper seam in slopos-ostd/src/mm/dma.rs is the swap point). Until then, loudly leave the raw-phys queue path alone — it is the only working data path.

5. Open Questions & Risks

Cross-cutting open questions

QuestionRecommendation
Binding storage for unbindProbeOutcome::Bound is a unit variant and the registry builds the Binding from the entry name; owned per-binding state needs a shape when remove arrives. Given the MetaSlot vtable-identity footgun (never use a fn-ptr/vtable address as cross-crate identity), prefer an opaque KBox<()> + typed remove fn-pointer over KBox<dyn DriverInstance>. The slot type is registry-local and changeable.
Where the Bus trait livesostd if it can be expressed without naming bus device types (associated types may suffice); drivers-crate driver_core otherwise. Decide by what keeps ostd free of PciDeviceInfo — the same constraint that placed BoundDevice in the drivers crate.
Crate splitSingle slopos-drivers crate now (lowest friction). Per-subsystem crates remain viable via KEEP + -u/--whole-archive — not blocked by DCE. Revisit when compile time hurts.
Phase-1 triggerGate platform_driver! on the first driver needing a deferred-probe parent-bus dependency (the thing the magic priority-82 integer currently fakes).

Top risks

  • Lock-ordering regressions. The split-lock safety case rests on an acyclic acquisition graph, not a numeric level gate: the enum and claim locks are advisory ranks under cycle detection, taken one-at-a-time, never nested, probe lock-free. The generic probe_bus must preserve exactly this; copying a device array out blows the 2 KiB gate, and re-locking the enum lock inside probe deadlocks.
  • devres lifetime across unbind. If the bag drops at the wrong time, live MMIO/IRQ resources are released out from under a bound driver → UAF/spurious unmap. OwnedIrq drop order (handle before line) is critical; Binding-above-Devres slot order is the quiesce-before-release guarantee.
  • VA leak bound. IoMem has no Drop; the deferred-probe fixpoint must cap retries per (driver,device) or a driver that maps a BAR then fails on every retry leaks a BAR-VA window per attempt.
  • Scanout re-claim (hotplug). Mid-session GPU→GPU takeover touches COMPOSITOR_FB_ACQUIRED and the splash/vconsole/GpuControl/mouse-bounds re-pointing; eviction must re-point all of them or the console disappears on takeover. Reserve-before-reset must be honored by every GPU provider.
  • DMA non-migration. A "tidy unification" routing virtio through DmaCoherent would regress the only working data path — the migration is gated on a real VT-d mapper, nothing else.

6. Execution Order

  1. Wait for the Phase-1 gate. The Bus model is XL effort with no payoff until a second platform device exists; boot_init! covers today's device count. When the gate trips (first deferred-probe parent-bus dependency), land the trait + generic probe_bus + PCI-through-generic first, behaviour-preserving, then the gated platform registry.
  2. Phase-2 items land independently as their triggers appear: the fixpoint queue with the first real Deferred producer, remove with the first unbind consumer, hotplug/re-claim only after the compositor-park protocol is designed.
  3. Throughout: keep one slopos-drivers crate; re-run check_stack_sizes.sh / check_unsafe_outside_ostd.sh / check_kernel_softfloat.sh after each phase; gate every test-only dummy driver behind cfg(tests=on) side-table registration so it never ships in .driver_registry.
