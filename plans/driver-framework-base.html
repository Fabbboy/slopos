SlopOS Driver-Framework BASE

An implementation-ready, phase-organized plan for the reusable foundations that make adding any future driver trivial and correct — declarative match-tables, device↔driver binding, probe priority, a singleton-resource arbiter, managed-resource (devres) vending, DMA base wiring, and a unified Bus model. 1. Purpose & Scope

Today a new PCI driver self-registers via a #[repr(C)] link-section static (drivers/src/pci.rs:171-192, gathered by link.ld:74-78), but the probe loop (drivers/src/pci.rs:1173-1195) has no ownership model: every matcher probes every matching device, nothing records "device N is owned by driver X", and the GPU smuggles arbitration into matches() via a global GPU_ENABLED atomic. This document specifies the base that turns that loop into a world-class registry and gives probe() a safe capability handle for hardware resources.

In scope (the base): the singleton-resource arbiter, declarative id_table matching, device↔driver binding/claim with split-lock discipline, probe priority, the BoundDevice/devres managed-resource layer, wiring the dead DmaCoherent path with an identity IOMMU mapper, lifting MSI-X into a shared driver-core, the unified Bus trait, and the crate/file convention.

Out of scope: the xe driver's internals (GGTT, forcewake, display mode programming) — owned by plans/xe-driver-roadmap.md. xe appears here only as the worked example proving the base is "right".

2. Principles & Constraints

Every design decision below is bounded by SlopOS's framekernel discipline. These are not guidelines — they are CI-enforced invariants the implementation must satisfy.

  • Unsafe only in slopos-ostd. The driver crate is #![forbid(unsafe_code)]. Every new primitive a driver touches — the Bus trait, BoundDevice, Devres, the arbiter, the match-tables, the rewritten probe loop — is pure-safe Rust over ostd primitives (KBox/KVec/KBTreeMap/SpinLock/IrqAllocator/DmaCoherent/IoMem). The one small ostd addition (an OwnedIrq RAII pair) keeps its own unsafe internal. scripts/check_unsafe_outside_ostd.sh stays green.
  • 2 KiB per-function stack-frame gate. The probe loop must never copy the [PciDeviceInfo; PCI_MAX_DEVICES] array onto a frame (pci.rs:1174-1178). All owned binding state is built off-stack via KBox::try_init(T::init_…()); only a single PciDeviceInfo (tens of bytes) or a fat-pointer Binding (~24 B) ever crosses a frame. scripts/check_stack_sizes.sh is re-run on builddir/kernel.elf after each phase.
  • Soft-float. Matching, binding, and arbitration are integer/pointer math and fn-pointer dispatch — zero XMM/YMM. scripts/check_kernel_softfloat.sh is unaffected.
  • Link-section registration is sacred. .driver_registry (link.ld:74-78) stays KEEP'd; entries grow fields but remain #[repr(C)] rodata. Adding a driver stays purely additive — no central list, no init-order dependency, no global mutable vector.
  • No heap alloc under an IRQ-off cli-lock. The buddy allocator's LUF reuse path does a hidden cross-CPU TLB drain; allocating under a held cli-lock risks the slab-across-LUF-drain deadlock. The split-lock design ensures probe() (and its heap-allocating attach) run with neither ENUM_STATE nor the claim lock held.
  • QEMU-testability via virtio. The entire base is exercisable under just test on q35 with virtio-blk/net/gpu: binding, dup-claim prevention, priority ordering, deferred-probe, devres teardown, the arbiter, and DmaCoherent-on-identity-mapper. Only xe's display internals need real Intel HW. Test-only dummy drivers are cfg(tests=on)-gated and registered from a tests-side helper (see Phase 2 → "Test-driver registration mechanism") so they never land in a shipped .driver_registry.

4. Target Base Architecture

Two layers. The ostd trust domain owns all unsafe and exposes a safe device model (Bus trait, BoundDevice/devres, the arbiter primitive). The driver crate declares tables and writes typed probes, reaching hardware only through the capability handle. The arbiter lives below video (in kernel-services) and stores only provider-supplied fn-pointers, so no dependency edge inverts.

Core types at a glance.
  • Bus trait (ostd): associated Device/MatchKey/DriverEntry types + drivers()/device_count()/matches()/priority()/probe(). PCI first; platform/ACPI second (gated). One generic probe_bus<B> matchmaker drives all buses.
  • PciDriverEntry (link-section static): grows match_table: &'static [PciMatch], priority: u8, an optional imperative fallback, and probe -> Result<ProbeOutcome, ProbeError>.
  • BoundDevice/Devres: the capability handed to probe; vends RAII Mmio/IrqBinding/Dma, all released on probe-failure (and future unbind).
  • SingletonResource<P> → ScanoutProvider: claim-by-priority reservation before any destructive reset; eviction through the displaced provider's own evict fn.

API sketch

// kernel-services/src/syscall_services/scanout.rs
#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub enum ClaimOutcome { Won, Lost, LostTie }

pub struct SingletonResource<P: Copy + 'static> { /* SpinLock<ArbiterState<P>>, name */ }

impl<P: Copy + 'static> SingletonResource<P> {
    pub const fn new(name: &'static str) -> Self;
    // PHASE A: pure-priority reservation, touches NO hardware, lock released on return.
    pub fn claim(&'static self, priority: i32) -> ClaimOutcome;
    // PHASE B: winner commits after its reset+init succeeds; evicts displaced owner
    //          via the OLD provider's evict fn (callback run AFTER lock dropped).
    pub fn commit_install(&'static self, new: P, priority: i32,
                          evict_with: impl FnOnce(Option<P>));
    pub fn abort_claim(&'static self);          // winner whose reset FAILED
    pub fn current(&'static self) -> Option<P>;
}

#[derive(Clone, Copy)]
pub struct ScanoutProvider {
    pub id: ScanoutId,
    pub priority: i32,
    pub install: fn(ctx: &InstallCtx) -> bool, // body = boot_drivers.rs:357-386
    pub evict:   fn(),                          // firmware = no-op
}
pub enum ScanoutId { FirmwareFb, VirtioGpu, IntelXe }

pub struct InstallCtx {                          // passed BY REFERENCE (2 KiB gate)
    pub fb: slopos_abi::FramebufferData,         // small Copy: *mut u8 + DisplayInfo
    pub flush: fn(*const slopos_abi::damage::DamageRect, u32) -> core::ffi::c_int,
    pub gpu_control: Option<GpuControlFns>,
}

pub static SCANOUT: SingletonResource<ScanoutProvider> = SingletonResource::new("scanout");

// single-source-of-truth priority ladder
pub const PRIO_FIRMWARE_FB: i32 = 0;       // passive default, always losable
pub const PRIO_VIRTIO_GPU:  i32 = 30;
pub const PRIO_INTEL_XE:    i32 = 50;
pub const PRIO_CMDLINE_HINT_BUMP: i32 = 100; // `video=xe` folds into priority, never a gate

Algorithm (claim protocol, driver-probe side)

1. Pure matches() passed (vendor/class) — NO GPU_ENABLED read anymore.
2. RESERVE: let prio = base + cmdline_hint_bump(); match SCANOUT.claim(prio):
   - Won            -> proceed.
   - Lost / LostTie -> log, return Ok(Declined) WITHOUT touching hardware.
                       (the literal "losers stay passive" guarantee)
3. WON path only: do the destructive reset + scanout-resource create.
   - On reset/init failure: SCANOUT.abort_claim() (restores prior owner) + return Err(DeviceFault).
4. COMMIT: build InstallCtx (fb backing, flush fn, GpuControlFns) and the provider me.
   SCANOUT.commit_install(me, prio, |displaced| if let Some(p)=displaced { (p.evict)() });
   -> records new owner, clears reservation, evicts displaced via ITS evict fn.
      Lock is DROPPED before evict.
5. (me.install)(&ctx): runs the boot_drivers.rs:357-386 body — init_with_display_info,
   register_flush_callback, register_gpu_control, vconsole::register_framebuffer,
   sync_mouse_bounds, show_splash. Lock already dropped (GPU install blocks on completion).

Firmware default: video::init calls claim(PRIO_FIRMWARE_FB) (wins the empty arbiter) then commit_install(firmware, 0, |_|{}); firmware install is a no-op (already direct-write), firmware evict is empty. Eviction model: firmware→GPU is a provider-swap (install the flush where there was None + re-point fb/vconsole/gpu_control/mouse/splash), not a callback-removal. The symmetric GPU→GPU uninstall/reinstall is deferred to Phase 5.

Framekernel notes

  • Zero new unsafe — pure fn-pointer plumbing in kernel-services (already #![forbid(unsafe_code)]). NOT placed in ostd dev (would inflate tcb-ratio for zero unsafe).
  • The arbiter SpinLock is taken only for the brief reserve/commit window and released before any device reset, evict, or install body runs — mirroring the framebuffer_flush lock-drop at framebuffer.rs:184-197 and the slab-across-LUF-drain lesson. Non-reentrant: the arbiter never re-locks itself from inside a callback.
  • 2 KiB stack gate on the commit path. InstallCtx is passed by reference; ScanoutProvider is ~40 B of Copy fn-ptrs. slopos_abi::FramebufferData is just a *mut u8 + a DisplayInfo (a handful of integers — small Copy, verified abi/src/display.rs:94), so building InstallCtx at step 4 does not bloat the probe frame. Re-run check_stack_sizes.sh on both pci_probe_drivers and the commit/install path (the install body re-points splash/vconsole and could grow); if it ever approaches the gate, hold fb as &FramebufferData or build InstallCtx off-stack.
  • No heap under the lock (providers are inline Copy tables in the static). Registration is a plain static, not link-section-gathered, so no shipped-image leak concern for the arbiter itself.

What it unblocks

One-driver-per-device mutual exclusion; O(1) match at scale ("thousands of drivers"); specific-beats-generic ordering; the deferred-probe substrate. This is the #1 scaling base and a hard prerequisite for Phase 3's lock-free attach.

Algorithm (rewritten pci_probe_drivers — split-lock, priority-ordered)

1. BUILD INDEX (once, off the device lock):
   let idx = MatchIndex::build()?;     // walks driver_registry_iter() ONCE (+ TEST_DRIVERS if tests=on)
   for entry e at link index i, for m in e.match_table:
       insert i into by_vd[m.vd_key()] / by_cs[m.cs_key()];
       if m is ClassOnly OR e.fallback.is_some(): push i into catch_all.
   sort every bucket by (entry.priority, link-index) ascending  (lower binds first).
   // by_vd/by_cs/catch_all are ostd collections in a function-local — built once, dropped at fn end.

2. PROBE LOOP (device-outer, candidates-inner — inverted from today):
   for dev_idx in 0..device_count:
     if CLAIMED_BY.lock().slots[dev_idx].is_claimed(): continue;   // one driver per device
     let dev = pci_device_at(dev_idx)?;                            // single-element copy, ENUM_STATE RELEASED
     let mut cands: KVec<u16> = KVec::new();
     idx.candidates_for(&dev, &mut cands);                         // priority-sorted, dedup'd
     for &drv_i in &cands:
       let e = &idx.entries[drv_i];
       if !e.match_table_matches(&dev) && !e.fallback.map_or(false, |f| f(&dev)): continue;
       let mut bound = BoundDevice::new(&dev, &mut slot.devres);   // Phase 3 capability
       match (e.probe)(&mut bound) {                               // NO lock held here
         Ok(Bound(binding)) => {
             CLAIMED_BY.lock().slots[dev_idx] = Claimed(binding);  // registry records, post-Ok
             break;                                                // device bound; stop offering it
         }
         Ok(Declined)        => continue;                          // try next, lower-priority driver
         Err(Deferred)       => push (drv_i, dev_idx) onto DEFERRED local; continue;
         Err(other)          => klog the typed reason; continue;
       }

3. DEFERRED FIXPOINT (substrate; full queue is Phase 5): one bounded retry pass (N=1)
   re-runs step-2 body for each still-Unclaimed (drv_i, dev_idx). The (drv_i,dev_idx)
   worklist shape is forward-compatible with the Phase-5 retry-to-fixpoint queue.

LOCK DISCIPLINE (resolves the §3.1 hazard):
 - SlopOS lock "levels" are ADVISORY RANK HINTS under a cycle-detection (lockdep-style)
   model, NOT a strict numeric gate. The real invariant is "the acquisition graph stays
   acyclic". (lock_graph.rs:99-100: LOCK_LEVEL_RESOURCE=1, LOCK_LEVEL_REGISTRY=2.)
 - ENUM_STATE (REGISTRY, level 2): guards ONLY the read-only device table. Taken briefly
   inside pci_device_at() for a single-element copy. NEVER held across probe.
 - CLAIMED_BY (RESOURCE, level 1): guards ONLY the binding slots. Taken for is_claimed()
   and the single-slot Claimed write. NEVER held across probe.
 - The two locks are NEVER NESTED: pci_device_at() releases ENUM_STATE before CLAIMED_BY
   is taken (and vice versa). No edge is ever added between them -> acyclic graph, the
   cycle detector stays satisfied regardless of which level number is larger.
 - probe() runs lock-free: today's reentrancy deadlock is structurally GONE.

Algorithm (resource lifecycle)

1. Registry creates a per-device binding slot containing an empty Devres (in the Phase-2
   split-out claimed_by table, NOT on the probe-loop stack).
2. Registry builds BoundDevice { info: &devices[idx], res: &mut slot.devres } and calls probe.
3. Each vend call does ONE fallible acquisition then res.attach(resource):
   a. attach heap-boxes via KBox::try_new (resource rvalue never bloats probe's frame),
      unsizes to KBox<dyn ResourceObject>, pushes the cell, returns a &T reborrow.
   b. On try_new/try_push failure the resource's own Drop runs immediately -> no leak.
4. PROBE-FAILURE: probe returns Err. Registry drops the slot's Devres. KVec drops cells LIFO:
   DmaCoherent.unmap -> IrqBinding(handle then line) -> IoMem(no-op today). Device stays offerable.
5. PROBE-SUCCESS: registry moves Binding AND the populated Devres into the claimed_by slot.
   Store Binding ABOVE Devres so on a FUTURE unbind the driver Drop (quiesce: mask IRQs,
   stop queues) runs BEFORE DmaCoherent.unmap races in-flight DMA.

IDENTITY MAPPER & DEFAULT-DENY:
6. A boot_init! step at ~prio 78 calls register_identity_dma_mapper(token); from there
   current_iommu_mapper() returns Some and DmaCoherent::alloc no longer hits NotInitialised

// slopos-ostd/src/dev/bind.rs — ONE bus-agnostic matchmaker.
// BSP-only at boot; SMP-reentrant for the Phase-5 hotplug rescan (the ClaimTable
// locks are real SpinLocks acquired one-at-a-time, never nested across buses).
pub fn probe_bus<B: Bus>(claims: &ClaimTable) {
    let order = priority_order::<B>();          // KVec<u16> of entry indices, sorted once
    for &ei in order.iter() {
        let e = &B::drivers()[ei as usize];
        for idx in 0..B::device_count() {
            if claims.is_claimed(B::NAME, idx) { continue; }   // one driver per device
            if !B::matches(e, idx)            { continue; }
            match B::probe(e, idx) {
                Ok(b)                       => claims.record(B::NAME, idx, b),  // by index, POST-probe
                Err(ProbeOutcome::Declined) => {}                              // arbiter loss: stay passive
                Err(ProbeOutcome::Deferred) => claims.defer(B::NAME, ei, idx), // future fixpoint
                Err(ProbeOutcome::Failed(why)) => klog_warn!(..),
            }
        }
    }
}

  • The Bus trait, probe_bus, and the macros are pure-safe glue; all unsafe lives in the ostd primitives BoundDevice wraps (MmioRegion, IrqAllocator::alloc, DmaCoherent::alloc).
  • Link sections stay separate (not merged) so each bus carries its own #[repr(C)] entry type without a tagged union; the gated .platform_registry mirrors .driver_registry with its own __start_/__stop_ brackets.
  • DCE note: #[used] defeats intra-crate DCE but does NOT force an rlib member to link; a future per-subsystem crate split needs KEEP + -u<sym>/--whole-archive per driver archive (the Asterinas/RfL idiom). Sequencing question: introduce Bus in Phase 2 (its first payoff is binding/claim) or Phase 4 — this plan recommends folding the generic probe_bus<B> shape in at Phase 4 once PCI's binding is proven.

  • FUTURE remove fn on the binding (the slot already stores Binding above Devres so driver-quiesce-then-resource-release drop order is correct).

6. Writing a New Driver (the payoff)

The whole base exists to make this trivial. After Phases 2–3, a complete PCI driver is one file plus one pub mod line. No feature flag, no manual boot wiring, no special-casing — the registry records ownership, devres releases resources on any early-return, and the arbiter handles singleton resources.

The minimal template — entire driver in drivers/src/foo.rs

use slopos_ostd::dev::BoundDevice;
use slopos_ostd::mm::heap::KBox;
use crate::pci::{Binding, PciMatch, ProbeError, ProbeOutcome};

struct FooState { /* regs, irq binding handle, ring buffers... */ }
impl crate::pci::DriverInstance for FooState {}

fn foo_probe(dev: &mut BoundDevice<'_>) -> Result<ProbeOutcome, ProbeError> {
    let regs = dev.map_bar(0, 0, 0x1000).map_err(|_| ProbeError::Unsupported)?;
    // request_msix is self-sufficient: it discovers + maps the MSI-X table from the
    // device's BARs internally. The driver passes only the entry index + handler —
    // there is NO free `table` variable to construct.
    let _irq = dev.request_msix(0, |_ctx| { /* IRQ handler */ })
                  .map_err(|_| ProbeError::Unsupported)?;
    // owned state built OFF-STACK via KBox::try_init (2 KiB gate safe):
    let state = KBox::try_init(FooState::init(regs))
        .map_err(|_| ProbeError::OutOfMemory)?;
    // resources auto-release on ANY `?` early-return above (devres LIFO drop);
    // on Ok the registry records the claim by index, post-return.
    Ok(ProbeOutcome::Bound(Binding::owning("foo-nic", state)))
}

crate::pci_driver! {
    pub static FOO_DRIVER = {
        name:        "foo-nic",
        match_table: &[PciMatch::VendorDevice { vendor: 0x1af4, device: 0x1000 }],
        priority:    128,           // mid; lower binds before a generic fallback
        probe:       foo_probe,
    };
}

Then one line in drivers/src/lib.rs: pub mod foo;. That is the complete driver. The linker gathers FOO_DRIVER into .driver_registry; pci_probe_drivers finds it via the boot-built index, offers it the matching device in priority order, and records the binding.

If a driver needs the MSI-X table for multiple entries or wants to inspect it first, call let table = dev.msix_table()?; once and pass entry_idx per vector — but the common case above never touches a table binding directly.

The xe worked example — "just another driver"

xe proves the base is right: after the deflag it is a single drivers/src/xe.rs (the 5-file directory collapses in, register constants become an inner mod regs), with no xe-gpu feature, no manual xe_probe in boot, no VideoBackend::Xe. Its only extra step over foo is that, being a GPU, it claims the scanout singleton:

fn xe_probe(dev: &mut BoundDevice<'_>) -> Result<ProbeOutcome, ProbeError> {
    // 1. RESERVE the scanout on PRIORITY ALONE — before any destructive reset.
    let prio = PRIO_INTEL_XE + cmdline_hint_bump();   // `video=xe` folds into priority
    match SCANOUT.claim(prio) {
        ClaimOutcome::Won => {}                          // proceed
        // 2. Lost -> stay passive; firmware framebuffer keeps the display. NO hardware touched.
        _ => return Ok(ProbeOutcome::Declined),
    }
    // 3. WON: map BARs, do xe-roadmap internals (GGTT/forcewake/mode-set — out of scope here).
    let regs = dev.map_bar(0, 0, XE_MMIO_LEN).map_err(|_| ProbeError::Unsupported)?;
    let state = KBox::try_init(XeState::init(regs)).map_err(|_| ProbeError::OutOfMemory)?;
    // 4. COMMIT + install: evict the displaced (firmware) provider via ITS evict fn.
    SCANOUT.commit_install(XE_SCANOUT_PROVIDER, prio,
        |displaced| if let Some(p) = displaced { (p.evict)() });
    Ok(ProbeOutcome::Bound(Binding::owning("intel-xe", state)))
}

crate::pci_driver! {
    pub static XE_DRIVER = {
        name:        "intel-xe",
        match_table: &[PciMatch::VendorClass { vendor: 0x8086, class: PCI_CLASS_DISPLAY }],
        priority:    50,            // beats a future generic VGA fallback
        probe:       xe_probe,
    };
}

Both GPUs (virtio-gpu, xe) are now plain pci_driver!s. set_enabled/GPU_ENABLED and the boot scanout dance are gone; boot_drivers.rs:308-410 collapses to pci_init(); pci_probe_drivers();. The reserve-before-reset protocol means a losing GPU never tears down the firmware scanout it can't restore.

Top risks

  • Boot scanout handoff (Phase 1). Touches boot_drivers.rs:357-386 and COMPOSITOR_FB_ACQUIRED; eviction must re-point splash/vconsole/GpuControl/mouse-bounds or the boot console disappears on takeover. Reserve-before-reset must be honored by every GPU provider.
  • Lock-ordering reasoning (Phase 2). The split-lock safety case rests on an acyclic acquisition graph, not on a numeric level gate: LOCK_LEVEL_RESOURCE is 1 and LOCK_LEVEL_REGISTRY is 2 (slopos-ostd/src/sync/lock_graph.rs:99-100), so RESOURCE < REGISTRY numerically — but the levels are advisory rank hints under cycle detection. The real invariant is that pci_device_at releases ENUM_STATE before CLAIMED_BY is taken and the two are never nested. A regression that re-locks ENUM_STATE inside probe deadlocks (non-reentrant SpinLock); copying the device array out blows the 2 KiB gate. The split-lock + pci_device_at single-element copy are the load-bearing mitigations.
  • devres arena lifetime (Phase 3). If the arena drops at the wrong time, live MMIO/IRQ resources are released out from under a bound driver → UAF/spurious unmap. OwnedIrq drop order (handle before line) is critical. Heap alloc in attach must run lock-free (couples to Phase 2). IoMem has no Drop yet, so repeated defer-then-fail leaks one BAR-VA window per attempt — cap the retries.
  • DMA non-migration (Phase 3). A future "tidy unification" routing virtio through DmaCoherent would regress the only working data path — loudly document the decision at the virtio queue-alloc site.
  • ACPI / cross-crate (Phase 4+). ACPI matching depends on the focused DSDT/AML walker; a per-subsystem rlib nobody names is silently DCE-dropped (needs force-link).

8. Recommended Execution Order

  1. Phase 1 first (arbiter). It is a standalone static, not part of the registry rewrite, and it directly unblocks the xe deflag's display handoff. The virtio-gpu path live-verifies it. Ships independently.
  2. Phase 2 next (match-tables + binding). The #1 scaling foundation and a hard prerequisite for Phase 3's lock-free attach. Land the split-lock discipline under an explicit "never-nested, acyclic graph" contract (RESOURCE=1 and REGISTRY=2 are advisory ranks, not the gate).
  3. Phase 3 (devres + DMA wiring + MSI-X lift). The real leak-fix win; wire the DMA base via the existing dma.rs:160 seam but leave the virtio data path alone; orchestrate MSI-X over the existing msix.rs/msi.rs/msi_common.rs.
  4. Phase 4 gated on a concrete second platform device; introduce the generic Bus/probe_bus<B> once PCI's binding is proven.
  5. Phase 5+ future-additive. Deferred-probe fixpoint, hotplug, unbind, more buses, opportunistic DMA migration — all enabled by the foundations laid in 1–3.

Throughout: keep one slopos-drivers crate, collapse xe/ to xe.rs, re-run check_stack_sizes.sh / check_unsafe_outside_ostd.sh / check_kernel_softfloat.sh after each phase, and gate every test-only dummy driver behind cfg(tests=on) registered from a tests-side helper (the register_test_driver side-table) so it never ships in .driver_registry.
