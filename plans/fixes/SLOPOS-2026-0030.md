# SLOPOS-2026-0030 — Ready-queue selection is strict priority with no aging backstop

**Status of this document:** design proposal only. Nothing in the tree is
modified by it. Written against `develop` at `0ccf1a9b`.

**Revision 2 — response to review.** The first draft was rejected. Every
blocking point is answered below in place; §0 is the index of what moved, so a
re-reviewer can check the deltas without re-reading the whole document. Two
reviewer points turned out to be *right in a way the draft did not anticipate*
and changed the design: the fair state is **not** reset between test scopes
(§5.5, `SCHEDULERS_INIT` short-circuits `init`), and the wheel's
no-wrap argument as originally written was a proof obligation the code could
violate rather than an enforced clamp (§5.1). One reviewer-implied point is
rebutted with code evidence rather than adopted: the preemption comparison does
**not** need a new rule (§5.5).

**Compliance statement (hard constraints).** `AGENTS.md` was read in full before
any code was inspected and is treated as binding. This design:

- keeps every `unsafe` line inside `slopos-ostd`. The `sched/` changes are pure
  safe Rust under the crate's existing `#![forbid(unsafe_code)]`; the one
  `slopos-ostd` change is a new plain-safe struct field plus safe accessors,
  adding **zero** `unsafe` lines (so `tcb_ratio.sh` moves only in the
  denominator, downward-favourably);
- allocates nothing. Every new data structure is an inline field of the existing
  per-CPU `PriorityRunQueue` (`.bss`, via `CpuLocal`) or an existing intrusive
  link slot on `Task`. `KBox`/`KVec`/`KArc` are not needed and `alloc::*` is not
  touched;
- adds no large stack frame. The selection path's locals are a `u64` bitmap and
  two indices; the bucket array is a field, never an rvalue, so no
  `KBox::try_init` is required and `check_stack_sizes.sh`'s 2 KiB cap is not
  approached;
- performs **no floating point and no vector arithmetic**. Every weight is a
  power of two held as a `log2` shift, so virtual-time scaling is two shifts —
  no multiply, no divide, no `u128`, no compiler-builtin division call. The
  `+soft-float` guarantee is untouched;
- takes concepts only. EEVDF, CFS/`vruntime`, WFQ virtual finish time, RT
  bandwidth throttling and MLFQ aging are *published algorithms*; the deadline
  and lag definitions below are restated from the Stoica & Abdel-Wahab 1995
  formulation and from publicly documented kernel *behaviour* (LWN's EEVDF
  articles, `Documentation/scheduler/sched-rt-group.rst`'s documented default
  numbers, Fuchsia's public fair-scheduler concept docs, Microsoft's documented
  priority-boost behaviour). **No line of code or prose is copied from Linux,
  seL4 or illumos.** §2 was rewritten in this revision to *paraphrase* every
  upstream argument it previously quoted verbatim: the facts (a default of
  950 000 µs in 1 000 000 µs, a boost that decays one level per completed slice,
  a deferred-dequeue mechanism motivated by sleep-at-end-of-slice gaming) are
  interface and behavioural facts and carry no copyright; the sentences that
  stated them were someone else's prose and are gone. No implementation comment
  in this design may name an upstream *file*; each may name the algorithm, the
  specification, or the documented behaviour;
- preserves the task-ownership discipline I1–I8 unchanged: the fair queue reuses
  the *same* `Link<Task, ReadyQueueRole>` slot and the *same*
  retain/reclaim protocol, so "linked implies owned" (I2) holds by construction
  and `SchedPlacement` gains no variant;
- is pinned by tests that fail without it — enumerated in §7. Two of them
  (`test_fair_low_is_not_starved_by_normal`, `utest_sched_starvation`) fail
  against the tree as it stands today and are the gate on the finding itself;
  the rest pin a named invariant of the new structure, and §7 now states for
  each one the *mutation to the new code* it rejects, so "n/a — new structure"
  is no longer an answer anywhere in the table.

### 1.1 Selection — confirmed, line number wrong

Ledger says `sched/src/per_cpu.rs:404-420`. Actual location is **357–373**:

```rust
// sched/src/per_cpu.rs:357
    pub fn dequeue_highest_priority(&self) -> Option<TaskRef> {
        let self_addr = self as *const _ as usize;
        if self_addr < 0xffffffff80000000 {
            klog_info!(
                "SCHED: BUG - dequeue_highest_priority called with invalid self=0x{:x}",
                self_addr
            );
            return None;
        }
        let _guard = self.queue_lock.lock();
        for queue in &self.ready_queues {
            if let Some(task) = queue.dequeue() {
                return Some(task);
            }
        }
        None
    }
```

The claim stands exactly as written: a linear scan of `ready_queues[0..5]`,
first non-empty wins, unconditionally, with no counter, no budget, no age and no
second chance. `ReadyQueue::dequeue` (`per_cpu.rs:101`) pops the list head, so
selection is *strict priority, FIFO within tier*.

It has **one caller**, `sched/src/scheduler.rs:989`, inside
`run_ready_task_from_idle`. That single call site is what makes this refactor
tractable: the entire selection policy of the kernel is reachable from one
function and one edge.

### 1.5 Facts the ledger does not record, which the fix has to respect

- **Preemption exists; selection is the gap.** `scheduler_timer_tick`
  (`scheduler.rs:1762`) decrements `time_slice_remaining`
  (`consume_time_slice`, `scheduler.rs:442`) and requests a reschedule when it
  hits zero — but only after `if scheduler_ready_count(cpu_id) == 0 { reset;
  return }`. So a `Normal` spinner *is* preempted every 10 ticks; the
  re-selection then hands the CPU straight back to the `Normal` tier. The bug is
  100% in the pick, not in the preempt.
- **The quantum is a flat constant.** `SCHED_DEFAULT_TIME_SLICE = 10`
  (`scheduler.rs:104`) ticks at `LAPIC_TIMER_PERIOD_MS = 10` ⇒ a 100 ms slice for
  every task regardless of tier or load. That is a second, independent fairness
  defect: 100 ms is ~6 frames at 60 Hz.
- **Work stealing partially masks the bug on SMP, and only there.**
  `steal_task` (`per_cpu.rs:433`) iterates `ready_queues.iter().rev()` — `Idle`
  first, then `Low` — and `steal_from_tail` refuses a queue of length ≤ 1
  (`per_cpu.rs:125–128`), and `try_steal_task_from_cpu` (`per_cpu.rs:771`)
  refuses a victim whose *total* ready count is ≤ 1 on top of that. So a
  starved `Low` task *can* be migrated to an idle CPU,
  but only when a second `Low` task exists on the victim, only after the
  3-tick cooldown, and only if some CPU is idle (`IMBALANCE_THRESHOLD = 2`,
  `work_steal.rs:19`). On a uniprocessor, or when every CPU carries a `Normal`
  spinner, the `Low` task never runs. The repro in the ledger is sound.
- **Preemption-on-wake compares raw priority bytes.**
  `newcomer_outranks_current` (`scheduler.rs:483`) is
  `new.priority.as_u8() < pcr::current_task_priority_for(cpu)`, reading the PCR
  byte published by `dispatch` (`scheduler.rs:206`). Any change to what
  "priority" means has to keep this comparison meaningful, or keep the byte.
- **There is exactly one scheduler lock.** `queue_lock: SpinLock<()>`
  (`per_cpu.rs:161`) with
  `lock_class!("PriorityRunQueue.queue_lock", LOCK_LEVEL_SCHEDULER)`
  (`per_cpu.rs:182–185`). Everything the fix adds must live under it or be
  lock-free, or the lockdep gate grows a class and an edge. `SpinLock::lock`
  (`slopos-ostd/src/sync/spin.rs:417`) takes a `PreemptGuard` **and** does
  `cli`, so the hold is IRQ-off and preempt-off: everything under it must be
  short and must not block.
- **Runtime accounting already exists.** `Task` carries `time_slice`,
  `time_slice_remaining`, `total_runtime` and `last_run_timestamp` as
  `AtomicU64`s (`slopos-ostd/src/task/kernel_task.rs:427–443`), and
  `task_record_context_switch` (`sched/src/task/task_stats.rs:24`) already
  computes `timestamp - last_run_timestamp` on every switch-out and adds it to
  `total_runtime`. **The measurement the fix needs is already taken and thrown
  away.** `slopos_kernel_services::clock::ticks_to_microseconds`
  (`kernel-services/src/clock.rs:45`) converts those TSC deltas — note that it
  does so *in `u128`*, which §5.5 has to work around, and that it returns `0`
  before the platform clock is up.
- **`unschedule_task` sweeps every CPU.** `scheduler.rs:838` loops
  `0..get_cpu_count()` calling `remove_task` on each, so `remove` must stay
  cheap **and** must keep answering "not mine" for every CPU that does not hold
  the task. This is the constraint that shapes `queue_slot` in §5.2.
- **The fixture does not reinitialise the run queues.** `KernelTestScope::enter`
  calls `init_scheduler` (`test_fixture.rs:139`) →
  `per_cpu::init_all_percpu_schedulers` (`scheduler.rs:1679`), which begins
  `if !SCHEDULERS_INIT.init_once() { return; }` (`per_cpu.rs:722`). After the
  first scope in a boot that returns immediately and `PriorityRunQueue::init`
  never runs. What *does* run on every scope, from `Drop`
  (`test_fixture.rs:201`), is `clear_all_cpu_queues` → `clear_cpu_queues`
  (`per_cpu.rs:1190`). Any per-CPU scheduler state the fix adds must therefore
  be reset **there**, not only in `init`. The first draft got this wrong; §5.5
  and test 14 carry the correction.

## 2. Prior art: what mature kernels settled on, and what they abandoned

> **Licensing note (revision 2).** This section previously quoted upstream
> mailing-list and documentation prose verbatim. `AGENTS.md`'s licensing
> discipline permits taking concepts, algorithms and documented behaviour from
> a GPL-2.0-only project but forbids copying its *prose*, and a design document
> in this repository is as much a shipped artifact as a source file. Every
> quotation below has therefore been replaced with a paraphrase of the
> *behavioural or numerical fact*. Nothing in the argument depended on the
> wording.

The literature is unusually clear here, because the industry ran the experiment
twice and both times abandoned the same thing.

**What was abandoned: heuristic interactivity boosting.** Linux's O(1)
scheduler (2.6.0–2.6.22) detected "interactive" tasks by sleep-time history and
granted a priority bonus. It was replaced because the heuristics were
unfalsifiable and gameable: a task could sleep strategically to harvest the
bonus. Con Kolivas's RSDL (LWN, March 2007) was proposed explicitly to *delete*
the heuristics; its argument was that a task which sleeps leaves part of its
entitlement at the higher levels unspent, so the interactive advantage falls out
of the accounting rather than out of a detector. The reason given for preferring
that shape was reviewability — an accounting rule can be reasoned about, whereas
a boost driven by process state history cannot. CFS then took the same
accounting idea in a cleaner form, and the EEVDF proposal in 2023 made the same
argument a third time, with deleting heuristic code as an explicit goal.

**What was abandoned: MLFQ aging as the primary mechanism.** RSDL's own
anti-starvation device was the "minor rotation" — a per-*level* quota that
pushes every task at a level down the staircase when the level's quota is spent,
which bounds the wait of tasks below. It works, and it is exactly the design
someone reaches for when patching a strict-priority scan. It did not survive,
because the bound it gives is expressed in staircase steps rather than in CPU
share: two tasks that both get "eventually scheduled" can still receive wildly
different bandwidth, and the parameters (levels, per-level quota, step size)
have no principled setting. Windows keeps decayed boosting as a *supplementary*
mechanism — its documented behaviour is that a boost decays by one priority
level per completed time slice and that a thread's dynamic priority never drops
below its base — but only for base priorities 0–15, and layered on a scheduler
that is otherwise strict priority, which is why a runaway Windows realtime
thread is still a hang.

**What was kept: proportional share over a virtual timeline.** Every general
purpose kernel that solved this converged on the same shape.

- **Linux CFS (2.6.23–6.5)** tracked `vruntime` per task — real runtime scaled by
  the inverse of weight — and always ran the smallest. Starvation-free by
  construction: a task not running accrues no `vruntime`, so the running set's
  clocks advance past it and it becomes the minimum. Nice values became weights,
  not tiers.
- **Linux EEVDF (6.6+)** replaced the pick. Each task has *lag* = (entitled CPU
  time) − (received CPU time); a task is *eligible* iff lag ≥ 0; among eligible
  tasks the one with the earliest *virtual deadline* (eligible time + its time
  slice, in virtual units) runs. Two published properties matter here: the sum
  of all lags is identically zero (so the eligible set is never empty while the
  queue is non-empty), and shorter slices produce earlier deadlines — which is
  how EEVDF expresses *latency* without expressing *bandwidth*, replacing the
  "latency nice" patch series. The 2024 follow-up added deferred dequeue so a
  sleeping task's negative lag decays over *virtual* time rather than wall time;
  the documented motivation is that forgiving lag immediately at sleep lets a
  task game the scheduler by sleeping briefly at the end of its slice. That is
  the debt-laundering attack, and it is the attack §5.6 below has to defend
  against.
- **Fuchsia/Zircon** independently landed on weighted fair queuing over a
  virtual timeline ordered by virtual finish time in a WAVL tree. Its public
  concept documentation states the property this finding needs directly:
  proportional division is starvation-free for every thread regardless of how
  small its weight is relative to the others, and that property is what
  prevents unbounded priority inversion. Its scheduling *period* stretches with
  the number of competing threads so that each still gets a minimum granularity.
  Latency-critical work is *not* expressed as a higher priority but as a separate
  **deadline** discipline with a declared capacity and period — a bounded budget,
  not an unbounded precedence.
- **FreeBSD ULE** is the outlier worth naming honestly: `sched_ule(4)` documents
  that it detects interactive applications by heuristic and schedules them
  preferentially under load, on top of per-CPU run queues with topology-aware
  affinity. It is a
  counterexample to "everyone deleted the heuristics" but not to the conclusion:
  ULE still bounds starvation by decaying interactivity scores, i.e. by
  accounting, and its per-CPU-queue + affinity + stealing architecture is
  already what SlopOS has.

**What was kept for the privileged band: a bandwidth cap, not a priority cap.**
Strict priority is genuinely wanted for a small band of work; the industry
answer is to bound that band's *bandwidth* rather than to demote it. Linux's
documented defaults reserve 5 % of each period for non-realtime work —
`sched_rt_period_us` 1 000 000 µs against `sched_rt_runtime_us` 950 000 µs — and
the documented rationale is precisely this finding's threat model: the reserve
exists so that a runaway realtime task degrades the machine into something
recoverable instead of locking it up. Those two numbers are an interface fact,
which is why §5.4 adopts the same ratio. The argument recorded for keeping the
limit on by default was empirical rather than theoretical: unintentional RT
lockups were reported far more often than anyone deliberately wanting a machine
to stop.

**And what upstream learned was wrong with that cap.** Classic RT throttling
forces the CPU *idle* when the budget is spent even if nothing else wants to
run. The 2023 deadline-server work exists to fix exactly that; the behaviour is
described in the reporting on it as an artifact of how the throttle was
implemented rather than a wanted property, and the refined version starts the
server only once lower-priority tasks have actually been starved — measured
there as receiving no CPU time for half a second. **This design takes the
corrected version:
throttle the privileged band only when there is fair work waiting.** That is a
cheap conditional, and skipping it would import a five-year-old known bug.

**Synthesis for SlopOS.** The durable answer is the one three independent
kernels reached: *express ordinary work as weights over a virtual timeline, and
express privileged work as a bounded budget*. Aging bolted onto a priority scan
is the design each of them tried and left behind.

## 3. The minimal patch, and why it is not the answer

**The minimal patch.** Add a per-CPU `u8` counter to `PriorityRunQueue`; in
`dequeue_highest_priority`, every `N`-th call (say `N = 16`) start the scan at
the *lowest* non-empty queue instead of the highest. Six lines, no new fields on
`Task`, no ostd change, no gate movement beyond the test count.

It genuinely closes the literal finding: `Low` would run 1/16 of the time, so
"the `Low` task never runs" becomes false.

**Why it is insufficient.**

1. **`N` is unfalsifiable.** There is no measurement that makes 16 right and 8
   wrong. Every future argument about scheduling ends in a fight over a magic
   number nobody can defend, which is the exact failure mode the O(1)
   scheduler's heuristics died of.
2. **It fixes tier-vs-tier and leaves task-vs-task untouched.** Two `Normal`
   tasks still divide the CPU by *FIFO of a 100 ms quantum* with no accounting
   whatsoever. A task that never blocks and a task that blocks constantly get
   wildly different service and nothing records it. The finding is one visible
   instance of "the scheduler has no notion of who is owed what"; the patch
   papers over the instance.
3. **It leaves `High` unbounded.** A compositor bug — `/bin/compositor` is the
   one program granted `High` — still hangs the machine, since the patch's
   rotation would starve *everything else* 15/16 of the time rather than 16/16.
   That is the availability failure Linux's throttle default exists to prevent.
4. **It has no diagnostic surface.** After the patch, the honest answer to "is
   this workload being scheduled fairly?" is still "nobody knows". There is
   nothing for the `sched` kconsole command to print and nothing for a ratchet to
   hold.
5. **It cannot express latency.** SlopOS has a compositor. The reason `High`
   exists at all is latency, and the reason it is dangerous is that priority is
   the wrong tool for latency — which is the entire published motivation for
   EEVDF's slice-derived deadlines. The patch entrenches the wrong tool.

**What the refactor buys over five years.**

- Every future scheduling question — "why is the terminal janky", "did the NAPI
  kthread get its share", "is this driver's kthread hogging" — becomes a
  *readable number* (`vruntime`, lag, weight sum, throttle count) rather than an
  argument.
- Latency becomes expressible without authority. Today the only way to say "run
  this promptly" is `High`, which is unbounded precedence handed out by program
  identity. With slice-derived deadlines, "promptly" is a *shorter slice* — which
  costs the task nothing in share and costs the system nothing in safety. That is
  a strictly better answer to the same request, and it removes the pressure to
  hand out `High` more widely.
- The privileged band gets a *bounded* failure mode. A runaway `High` task
  degrades the machine instead of hanging it, and says so in the log.
- The accounting is the natural home for the next three features SlopOS will
  want — per-process CPU share, cgroup-ish grouping, and a `SCHED_DEADLINE`-like
  class for audio/video. Each is an extension of a virtual timeline and none is
  an extension of a priority scan.
- It is a **one-call-site** replacement. The blast radius is bounded today and
  will not be in three years, once more code depends on `dequeue_highest_priority`
  semantics.

The refactor is therefore proposed, with one deliberate scope cut: **the EEVDF
eligibility test is explicitly out of scope for this change** (§8.1). The
eligibility test buys a *lateness bound*; the starvation freedom this finding
needs comes from the virtual timeline alone — CFS was already starvation-free
and EEVDF was merged for latency. Adding eligibility requires an augmented
ordered tree in `slopos-ostd`, i.e. new `unsafe` in the TCB, and that trade is
not justified by this finding.

## 4. Design overview

Three bands, per CPU.

| Band | Members | Ordering | Bounded by |
|---|---|---|---|
| **A — privileged** | `High`, `KernelIo` | strict priority, FIFO within tier (unchanged) | a per-CPU bandwidth budget, enforced *only while band B is non-empty* |
| **B — fair** | `Normal`, `Low` | weighted fair, ordered by virtual deadline over a calendar wheel | nothing; it is the fallback |
| **C — floor** | `Idle` | FIFO | nothing; selected only when A and B are empty |

`TaskPriority` keeps its five variants, its `repr(u8)` values, its publication
through the PCR byte and its position in the ABI. What changes is that `Normal`
and `Low` stop being *queue indices* and become *weights*: `Normal = 2^10`,
`Low = 2^6`, a 16:1 share ratio. No syscall changes, no new user-facing knob, no
new authority, and — as §5.5 shows with the existing test as evidence — no
change to the preemption comparison either.

Selection becomes:

```
pick(cpu):
    if band_A_nonempty and not band_A_throttled(cpu):
        return band_A.pop_highest_tier()
    if band_B_nonempty:
        return band_B.pop_earliest_virtual_deadline()
    if band_A_nonempty:                  # throttled, but nothing else wants the CPU
        return band_A.pop_highest_tier() # never force idle — the corrected throttle
    return band_C.pop()
```

Band B's ordering key is the EEVDF virtual deadline
`vdeadline = vruntime + virtual_slice`, with `virtual_slice = slice_ns` scaled by
the inverse weight. Because a task accrues `vruntime` only while running, a task
that does not run has a monotonically improving position, which is the
starvation-freedom argument. Because a *smaller slice* yields an earlier
deadline, latency is expressible without precedence — the published EEVDF
property, obtained here without the eligibility test.

Band B is stored as a **calendar wheel**: `NBUCKETS = 32` FIFO buckets, each an
existing `ReadyQueue`, indexed by `(vdeadline >> BUCKET_SHIFT) % NBUCKETS`, plus a
32-bit occupancy bitmap. Selection is one rotate and one `trailing_zeros` —
O(1), no tree, no allocation, and no new `unsafe` anywhere. Correctness of the
wheel rests on the live window `[min_vruntime, min_vruntime + HORIZON_VNS)`
containing every queued deadline, which is enforced from **both** ends: the
enqueue band clamps how far above the floor a task may be placed and the virtual
slice is capped, with `assert!(ENQUEUE_BAND_VNS + MAX_VSLICE_VNS < HORIZON_VNS)`
making the combination a build-time question (§5.1.2). Both clamps also count
when they fire, so a violation is observable and not merely asserted.

The cost is stated up front: 32 buckets × 24 B × 256 CPUs is ≈195 KiB of `.bss`
(§5.8), and bucket resolution is 4.19 ms, so ordering within a bucket is FIFO
rather than by deadline (§8 item 1b). Both are deliberate trades against the
alternative, which is an augmented ordered tree in `slopos-ostd` — i.e. new
`unsafe` in the TCB.

### 5.1 New file: `sched/src/fair.rs`

#### 5.1.1 Constants, and why each is representable

The first draft's constants were incoherent with the tick that drives
preemption. Preemption is tick-driven: `consume_time_slice`
(`scheduler.rs:442`) decrements a *tick* counter and the LAPIC period is 10 ms
(`scheduler.rs:25`). A 1 ms `MIN_GRANULARITY_NS` is therefore not a slice the
machine can deliver — it rounds to either zero ticks (never preempted) or one
tick (10 ms). The constants below are stated in nanoseconds because virtual
time is, but every one of them is a whole number of ticks.

```rust
/// The LAPIC tick, in nanoseconds. Must match `scheduler::LAPIC_TIMER_PERIOD_MS`;
/// the const assert below is what makes a divergence a build failure.
pub const TICK_NS: u64 = 10_000_000;

/// Target scheduling period: every runnable fair task should get the CPU once
/// per period. Six ticks — the period stretches under load (5.1.4), so this is
/// the *floor* on how often a task is reached, not a promise about slice size.
pub const TARGET_LATENCY_NS: u64 = 6 * TICK_NS;   // 60 ms

/// Smallest slice the tick can deliver. One tick: anything smaller is
/// unrepresentable, and rounding it down to zero would disable preemption.
pub const MIN_GRANULARITY_NS: u64 = TICK_NS;      // 10 ms

/// Largest slice. Three ticks, below today's flat ten, so the change strictly
/// improves worst-case latency rather than trading it.
pub const MAX_SLICE_NS: u64 = 3 * TICK_NS;        // 30 ms

/// A charge larger than this means the timestamp source lied (TSC reset,
/// migration across a non-invariant TSC, a VM exit). Clamped, not trusted,
/// and counted.
pub const MAX_CHARGE_NS: u64 = 1_000_000_000;

pub const NBUCKETS: usize = 32;
pub const BUCKET_SHIFT: u32 = 22;                 // 4_194_304 ns per bucket
pub const HORIZON_VNS: u64 = (NBUCKETS as u64) << BUCKET_SHIFT; // 134.2 ms
```

`const` assertions, all in `fair.rs`:

```rust
const _: () = assert!(NBUCKETS.is_power_of_two());
const _: () = assert!(MIN_GRANULARITY_NS <= MAX_SLICE_NS);
const _: () = assert!(MIN_GRANULARITY_NS % TICK_NS == 0);
const _: () = assert!(MAX_SLICE_NS % TICK_NS == 0);
const _: () = assert!(TARGET_LATENCY_NS % TICK_NS == 0);

/// The whole safety argument for the wheel (F3). `ENQUEUE_BAND_VNS` bounds how
/// far a queued task's `vruntime` may sit above `min_vruntime` (5.1.3) and
/// `MAX_VSLICE_VNS` bounds the deadline offset on top of it; their sum must
/// stay strictly inside one revolution or a deadline could land in a bucket
/// the scan has already passed and be treated as *earlier* than it is.
const _: () = assert!(ENQUEUE_BAND_VNS + MAX_VSLICE_VNS < HORIZON_VNS);
```

and one in `sched/src/scheduler.rs`, where `LAPIC_TIMER_PERIOD_MS` lives:


#### 5.1.2 `SchedWeight`

```rust
/// Inverse weight, held as a base-2 exponent so every scaling is a shift.
/// A zero or non-power-of-two weight would make the virtual clock lie or
/// divide by zero; a validated newtype makes neither representable. This is
/// the pattern `check_safe_contract_surface.sh` exists to reward: a
/// constructor that refuses, not a `# Safety` paragraph telling the caller
/// not to.
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct SchedWeight(u8);

impl SchedWeight {
    /// Reference exponent. `scale` multiplies by `1 << UNIT_SHIFT` before
    /// dividing by the weight, so a `UNIT_SHIFT`-weighted task's virtual time
    /// advances at exactly real time.
    pub const UNIT_SHIFT: u8 = 10;
    pub const NORMAL: Self = Self(10);   // weight 1024
    pub const LOW: Self = Self(6);       // weight 64 -> 1/16 of Normal
    const MIN_SHIFT: u8 = 6;
    const MAX_SHIFT: u8 = 14;

    /// The only constructor. `None` outside the sanctioned range.
    pub const fn from_shift(shift: u8) -> Option<Self> {
        if shift < Self::MIN_SHIFT || shift > Self::MAX_SHIFT {
            None
        } else {
            Some(Self(shift))
        }
    }

    #[inline]
    pub const fn raw_shift(self) -> u8 { self.0 }

    #[inline]
    pub const fn weight(self) -> u32 { 1u32 << self.0 }

    /// Real nanoseconds -> virtual nanoseconds.
    ///
    /// Two shifts. No multiply, no divide, no `u128`, so no call to the
    /// compiler's 128-bit division builtin and nothing for
    /// `check_kernel_softfloat.sh` to find. The clamp is what makes the left
    /// shift non-overflowing: `MAX_CHARGE_NS < 2^30`, `UNIT_SHIFT == 10`, so
    /// the intermediate is `< 2^40`.
    #[inline]
    pub const fn scale(self, real_ns: u64) -> u64 {
        let clamped = if real_ns > MAX_CHARGE_NS { MAX_CHARGE_NS } else { real_ns };
        (clamped << Self::UNIT_SHIFT) >> self.0
    }

    /// Band-B priorities only. Band A and band C never consult a weight.
    pub const fn for_priority(p: TaskPriority) -> Option<Self> {
        match p {
            TaskPriority::Normal => Some(Self::NORMAL),
            TaskPriority::Low => Some(Self::LOW),
            _ => None,
        }
    }
}

const _: () = assert!((MAX_CHARGE_NS << SchedWeight::UNIT_SHIFT) > MAX_CHARGE_NS);

/// Ceiling on the virtual-deadline offset, and on how far above the floor a
/// task may be placed. **Chosen, then asserted** — not derived from
/// `MAX_SLICE_NS`, because a `Low` task's unclamped virtual slice is 16x its
/// real one and would not fit.
pub const MAX_VSLICE_VNS: u64 = 48_000_000;   // 48 ms of virtual time
pub const ENQUEUE_BAND_VNS: u64 = 48_000_000; // 48 ms of virtual time
```

**The derived form is the defect the first draft shipped.** The draft wrote
`MAX_VDEADLINE_OFFSET_VNS = (MAX_SLICE_NS << UNIT_SHIFT) >> LOW.raw_shift()`
and asserted it against the horizon. At the draft's own `MAX_SLICE_NS = 8 ms`
that is 128 ms against a 134.2 ms horizon — it passes, but with 6 ms of margin,
and only because 8 ms happened to be small enough. Raise `MAX_SLICE_NS` by one
tick and the build breaks; raise it by three, as the tick-coherence fix in
5.1.1 requires, and the derived value is 480 ms against a 134.2 ms horizon. A
constant whose validity depends on an unrelated constant staying small is not
an enforced invariant, it is a coincidence with an assert next to it.

Two changes make it structural instead:

1. **The virtual slice is capped**, not merely derived:
   `vslice = min(weight.scale(slice_ns), MAX_VSLICE_VNS)`. A `Low` task gets a
   deadline no further out than 48 virtual ms even though its unclamped virtual
   slice would be 480. The effect on fairness is nil — the deadline decides
   *order*, the `vruntime` charge decides *share*, and the charge is not
   clamped — while the effect on the wheel is that the offset is bounded by
   construction rather than by arithmetic luck.
2. **The enqueue `vruntime` is clamped into a band** (5.1.3), which bounds the
   other term of the sum.

```rust
const _: () = assert!(ENQUEUE_BAND_VNS + MAX_VSLICE_VNS < HORIZON_VNS); // 96 < 134.2
```

The 38 ms of horizon left unused is deliberate margin: a future constant change
has somewhere to go before the assert fires, and the assert fires before the
wheel misbehaves rather than after.

#### 5.1.3 The enqueue band — the second half of the no-wrap argument

The first draft asserted F2 ("`min_vruntime` never exceeds any queued
`vdeadline`") and treated it as sufficient. It is not. F2 bounds the queue from
*below*; the wheel also needs a bound from *above*, because a task that slept
through ten periods and woke with a `vruntime` far ahead of the floor would
index a bucket more than one revolution out. The draft's sleeper-credit rule
clamped the *low* side only.

The rule is therefore symmetric, and it subsumes the separate work-steal
rebase the draft listed as its own call site:

```rust
/// Place `task`'s virtual clock into this queue's live band. The single
/// entry point for a task joining a fair queue, whichever way it arrived:
/// a fresh spawn, a wake, a preemption requeue, or a migration from
/// another CPU's timeline.
///
/// Low side: a sleeper is forgiven at most one period of debt, so waking
/// does not buy monopolisation (F7).
/// High side: a task cannot sit further ahead than the band, so the wheel
/// cannot wrap (F3). A task clamped down here is one that owes more than
/// the band can express; the clamp forgives the excess and counts it.
#[inline]
fn place_vruntime(&self, task: &Task) {
    let floor = self.min_vruntime.load(Ordering::Relaxed);
    let v = task.sched.vruntime();
    let low = floor.saturating_sub(SLEEPER_CREDIT_VNS);
    let high = floor.saturating_add(ENQUEUE_BAND_VNS);
    let placed = if v < low {
        low
    } else if v > high {
        self.band_clamped.fetch_add(1, Ordering::Relaxed);
        high
    } else {
        v
    };
    task.sched.set_vruntime(placed);
}

/// One scheduling period of forgiveness, no more.
pub const SLEEPER_CREDIT_VNS: u64 = TARGET_LATENCY_NS;
```

Because `place_vruntime` runs on *every* link into a fair queue, a task
migrated from a CPU whose `min_vruntime` is wildly different is re-based by the
same code that handles a wake. That is why §5.5 no longer carries a
work-steal-specific rebase: the draft's version read the victim's
`min_vruntime` after the steal had already released the victim's lock, i.e. it
read a value that could have moved. The band clamp needs only the *thief's*
floor, which is held under the thief's own lock at the moment of the link.

#### 5.1.4 `FairQueue`

```rust
/// Per-CPU weighted-fair queue.
///
/// **Placement:** an inline field of `PriorityRunQueue`, which is itself a
/// `CpuLocal` slot (`per_cpu.rs:676-702`), so this is per-CPU `.bss` and
/// never heap.
///
/// **Locking:** every mutating method is `_locked` and may only be called with
/// the owning `PriorityRunQueue::queue_lock` held. The fields are atomics so
/// the type stays `&self`-only (matching `ReadyQueue`, which is the same shape
/// for the same reason) and so the three read-only accessors below can be
/// called lock-free from the tick and the kconsole dump — not because the
/// mutations are lock-free. Every atomic op here is `Relaxed`: the lock
/// supplies the ordering for the mutating paths, and the lock-free readers are
/// diagnostics that tolerate a stale value.
pub(crate) struct FairQueue {
    buckets: [ReadyQueue; NBUCKETS],
    /// Bit `i` set iff `buckets[i]` is non-empty.
    occupancy: AtomicU32,
    /// Monotone floor over queued virtual runtimes. Advanced only by
    /// `pick_locked`, never rewound.
    min_vruntime: AtomicU64,
    nr_queued: AtomicU32,
    /// Sum of `weight()` over queued tasks, for slice sizing. `u64` because
    /// 8192 tasks x 2^14 is 2^27 — fits in u32, but the sum is also
    /// decremented on removal and a transient desync must not wrap.
    weight_sum: AtomicU64,
    /// Diagnostics, surfaced by the `sched` kconsole command and asserted by
    /// tests. Each non-zero value means a specific invariant needed rescuing.
    bucket_clamped: AtomicU32,
    band_clamped: AtomicU32,
    charge_clamped: AtomicU32,
    occupancy_repaired: AtomicU32,
}
```

Bodies for everything load-bearing:

```rust
impl FairQueue {
    pub(crate) const fn new() -> Self {
        Self {
            buckets: [const { ReadyQueue::new() }; NBUCKETS],
            occupancy: AtomicU32::new(0),
            min_vruntime: AtomicU64::new(0),
            nr_queued: AtomicU32::new(0),
            weight_sum: AtomicU64::new(0),
            bucket_clamped: AtomicU32::new(0),
            band_clamped: AtomicU32::new(0),
            charge_clamped: AtomicU32::new(0),
            occupancy_repaired: AtomicU32::new(0),
        }
    }

    /// Drop every queued task, releasing each parked owning reference, and
    /// return every scalar to its construction value.
    ///
    /// Called from `PriorityRunQueue::init` *and* from `clear_cpu_queues`,
    /// which is the one of the two that actually runs on a test-scope
    /// boundary (see 5.5).
    pub(crate) fn reset_locked(&self) {
        for bucket in &self.buckets {
            bucket.clear_with_ref_release();
        }
        self.occupancy.store(0, Ordering::Relaxed);
        self.min_vruntime.store(0, Ordering::Relaxed);
        self.nr_queued.store(0, Ordering::Relaxed);
        self.weight_sum.store(0, Ordering::Relaxed);
        self.bucket_clamped.store(0, Ordering::Relaxed);
        self.band_clamped.store(0, Ordering::Relaxed);
        self.charge_clamped.store(0, Ordering::Relaxed);
        self.occupancy_repaired.store(0, Ordering::Relaxed);
    }

    #[inline]
    fn bucket_of(vdeadline: u64) -> usize {
        ((vdeadline >> BUCKET_SHIFT) as usize) & (NBUCKETS - 1)
    }

    #[inline]
    fn weight_of(task: &Task) -> SchedWeight {
        SchedWeight::from_shift(task.sched.weight_shift()).unwrap_or(SchedWeight::NORMAL)
    }

    /// Slice for the next dispatch: the scheduling period divided over the
    /// competing set, floored at one tick and capped at three.
    ///
    /// Integer division by `nr`, which is a runtime value, so this is a real
    /// `div` — but on `u64`, which x86-64 does in hardware. It is not a
    /// `u128` division and pulls in no compiler builtin, so the softfloat
    /// gate is unaffected. Called once per dispatch, not per tick.
    pub(crate) fn slice_ns_locked(&self) -> u64 {
        let nr = self.nr_queued.load(Ordering::Relaxed).max(1) as u64;
        let raw = TARGET_LATENCY_NS / nr;
        raw.clamp(MIN_GRANULARITY_NS, MAX_SLICE_NS)
    }

    /// Link a task whose placement is already `ReadyQueue`.
    ///
    /// Returns the same tri-state as `ReadyQueue::link_preclaimed_with_status`
    /// (`per_cpu.rs:83`) — 0 linked, 1 already owned, -1 list error — because
    /// `publish_ready_fallback` (`scheduler.rs:487`) distinguishes all three
    /// and a collapse to a bool would make a never-published task look
    /// published.
    ///
    /// Ordering inside the lock is load-bearing: `queue_slot` is stamped
    /// *before* the link, and cleared only after a successful unlink, so a
    /// slot that names this queue always names a task that is either linked
    /// here or about to be. The `1` and `-1` arms roll the stamp back.
    pub(crate) fn link_locked(&self, cpu_id: u8, task: &TaskRef, slice_ns: u64) -> i32 {
        let body: &Task = task;
        let weight = Self::weight_of(body);

        self.place_vruntime(body);

        let vslice = weight.scale(slice_ns).min(MAX_VSLICE_VNS);
        body.sched.set_slice_ns(slice_ns.min(u32::MAX as u64) as u32);
        let vdeadline = body.sched.vruntime().saturating_add(vslice);

        let idx = self.bucket_index_checked(vdeadline);
        body.sched.set_queue_slot(cpu_id, idx as u16);

        let rc = self.buckets[idx].link_preclaimed_with_status(task);
        if rc == 0 {
            self.occupancy.fetch_or(1u32 << idx, Ordering::Relaxed);
            self.nr_queued.fetch_add(1, Ordering::Relaxed);
            self.weight_sum
                .fetch_add(weight.weight() as u64, Ordering::Relaxed);
        } else {
            body.sched.clear_queue_slot();
        }
        rc
    }

    /// Bucket for `vdeadline`, clamped into the live window at **both** ends.
    ///
    /// The low clamp is not defensive, it is load-bearing. `place_vruntime`
    /// deliberately places a credited sleeper *below* `min_vruntime`, and the
    /// scan starts at `bucket_of(min_vruntime)` and rotates **forward** — so a
    /// bucket below the floor would be reached last, ordering the task the
    /// credit was meant to favour dead last instead of first. Clamping to the
    /// cursor bucket puts it at the front, which is the intent, while its
    /// `vruntime` stays low so it keeps winning until the charge lifts it past
    /// the floor. That is what bounds the credit's effect to
    /// `SLEEPER_CREDIT_VNS` of virtual time rather than to a number of picks.
    ///
    /// The high clamp is defensive: F3 says it is unreachable, and test 5
    /// asserts the counter stays zero. Only the high clamp counts, because the
    /// low one is a normal occurrence.
    fn bucket_index_checked(&self, vdeadline: u64) -> usize {
        let floor = self.min_vruntime.load(Ordering::Relaxed);
        if vdeadline <= floor {
            return Self::bucket_of(floor);
        }
        let horizon = floor.saturating_add(HORIZON_VNS);
        if vdeadline >= horizon {
            self.bucket_clamped.fetch_add(1, Ordering::Relaxed);
            debug_assert!(false, "fair: vdeadline beyond the wheel horizon");
            return Self::bucket_of(horizon - 1);
        }
        Self::bucket_of(vdeadline)
    }

    /// Earliest virtual deadline; `None` if empty.
    ///
    /// One `rotate_right` and one `trailing_zeros`, both single integer
    /// instructions on x86-64. Locals: three `u64`s and two `usize`s, so the
    /// frame is nowhere near the 2 KiB cap.
    pub(crate) fn pick_locked(&self) -> Option<TaskRef> {
        let floor = self.min_vruntime.load(Ordering::Relaxed);
        let cursor = Self::bucket_of(floor);
        let occ = self.occupancy.load(Ordering::Relaxed);
        if occ == 0 {
            debug_assert_eq!(self.nr_queued.load(Ordering::Relaxed), 0);
            return None;
        }
        let rotated = occ.rotate_right(cursor as u32);
        let idx = (cursor + rotated.trailing_zeros() as usize) & (NBUCKETS - 1);

        let Some(task) = self.buckets[idx].dequeue() else {
            // F4 desync: the bitmap claimed a bucket the list did not have.
            self.repair_occupancy();
            return self.pick_after_repair();
        };

        if self.buckets[idx].is_empty() {
            self.occupancy.fetch_and(!(1u32 << idx), Ordering::Relaxed);
        }
        let body: &Task = &task;
        body.sched.clear_queue_slot();
        self.nr_queued.fetch_sub(1, Ordering::Relaxed);
        self.weight_sum.fetch_sub(
            Self::weight_of(body).weight() as u64,
            Ordering::Relaxed,
        );

        // F2: monotone, and never past any queued deadline.
        let v = body.sched.vruntime();
        if v > floor {
            self.min_vruntime.store(v, Ordering::Relaxed);
        }
        Some(task)
    }

    /// Rebuild the bitmap from the buckets. Bounded at 32 `is_empty` calls,
    /// each a relaxed load, so it is cheap enough to run inline on the
    /// (never-observed) desync path rather than deferring it.
    fn repair_occupancy(&self) {
        let mut mask = 0u32;
        for (i, bucket) in self.buckets.iter().enumerate() {
            if !bucket.is_empty() {
                mask |= 1u32 << i;
            }
        }
        self.occupancy.store(mask, Ordering::Relaxed);
        self.occupancy_repaired.fetch_add(1, Ordering::Relaxed);
        debug_assert!(false, "fair: occupancy bitmap desynced from buckets");
    }

    /// Remove a specific task, using the `(cpu, bucket)` it recorded.
    ///
    /// `-1` (`NotPresent`) for a task this queue does not hold, which is the
    /// answer 255 of 256 CPUs give on every `unschedule_task`
    /// (`scheduler.rs:838`) — so the fast path is two atomic loads and a
    /// comparison, strictly cheaper than today's `list.remove` walk.
    pub(crate) fn remove_locked(&self, cpu_id: u8, task: &Task) -> i32 {
        let Some((slot_cpu, bucket)) = task.sched.queue_slot() else {
            return self.remove_fallback(task);
        };
        if slot_cpu != cpu_id || bucket as usize >= NBUCKETS {
            return self.remove_fallback(task);
        }
        let idx = bucket as usize;
        let rc = self.buckets[idx].remove(task);
        if rc == 0 {
            if self.buckets[idx].is_empty() {
                self.occupancy.fetch_and(!(1u32 << idx), Ordering::Relaxed);
            }
            task.sched.clear_queue_slot();
            self.nr_queued.fetch_sub(1, Ordering::Relaxed);
            self.weight_sum.fetch_sub(
                Self::weight_of(task).weight() as u64,
                Ordering::Relaxed,
            );
        }
        rc
    }

    /// Under `debug_assertions` only, prove the slot was not lying: scan every
    /// bucket, and shout if the task is found where the slot said it was not.
    /// In a release kernel this is `-1` and nothing else, so the all-CPU
    /// sweep costs nothing.
    #[inline]
    fn remove_fallback(&self, task: &Task) -> i32 {
        #[cfg(debug_assertions)]
        {
            for (i, bucket) in self.buckets.iter().enumerate() {
                if bucket.remove(task) == 0 {
                    slopos_ostd::klog_info!(
                        "FAIR: BUG - task {} found in bucket {} with a stale queue_slot",
                        task.task_id,
                        i
                    );
                    if bucket.is_empty() {
                        self.occupancy.fetch_and(!(1u32 << i), Ordering::Relaxed);
                    }
                    task.sched.clear_queue_slot();
                    self.nr_queued.fetch_sub(1, Ordering::Relaxed);
                    self.weight_sum
                        .fetch_sub(Self::weight_of(task).weight() as u64, Ordering::Relaxed);
                    return 0;
                }
            }
        }
        -1
    }

    /// Latest-deadline task, for the thief. Refuses to empty the queue,
    /// matching `steal_from_tail`'s own `len() <= 1` guard
    /// (`per_cpu.rs:125-128`) — a thief that empties a queue creates the
    /// reverse imbalance the cooldown exists to prevent.
    pub(crate) fn steal_locked(&self) -> Option<TaskRef> {
        if self.nr_queued.load(Ordering::Relaxed) <= 1 {
            return None;
        }
        let occ = self.occupancy.load(Ordering::Relaxed);
        if occ == 0 {
            return None;
        }
        let cursor = Self::bucket_of(self.min_vruntime.load(Ordering::Relaxed));
        // Latest deadline = last set bit walking backwards from the cursor.
        let rotated = occ.rotate_right(cursor as u32);
        let back = 31 - rotated.leading_zeros() as usize;
        let idx = (cursor + back) & (NBUCKETS - 1);

        let task = self.buckets[idx].steal_from_tail()?;
        if self.buckets[idx].is_empty() {
            self.occupancy.fetch_and(!(1u32 << idx), Ordering::Relaxed);
        }
        let body: &Task = &task;
        body.sched.clear_queue_slot();
        self.nr_queued.fetch_sub(1, Ordering::Relaxed);
        self.weight_sum
            .fetch_sub(Self::weight_of(body).weight() as u64, Ordering::Relaxed);
        Some(task)
    }

    /// Charge real runtime to a task's virtual clock. Takes no lock: the
    /// task is off-queue (it just ran), the field is atomic, and the value is
    /// re-based by `place_vruntime` on the next link anyway.
    pub(crate) fn charge(&self, task: &Task, delta_ns: u64) {
        if delta_ns > MAX_CHARGE_NS {
            self.charge_clamped.fetch_add(1, Ordering::Relaxed);
        }
        let weight = Self::weight_of(task);
        let v = task.sched.vruntime();
        task.sched
            .set_vruntime(v.saturating_add(weight.scale(delta_ns)));
    }

    #[inline]
    pub(crate) fn nr_queued(&self) -> u32 { self.nr_queued.load(Ordering::Relaxed) }
    #[inline]
    pub(crate) fn is_empty(&self) -> bool { self.nr_queued() == 0 }
    #[inline]
    pub(crate) fn min_vruntime(&self) -> u64 { self.min_vruntime.load(Ordering::Relaxed) }

    pub(crate) fn stats(&self) -> FairStats { /* plain field reads */ }
```

**F2's proof, restated now that the code is concrete — and corrected.** The
first draft stated F2 as "`min_vruntime` never exceeds any queued `vdeadline`"
and offered the following argument: `pick_locked` advances `min_vruntime` only
to the `vruntime` of the task it just removed; that task held the earliest
deadline; every task satisfies `vruntime <= vdeadline`; therefore
`picked.vruntime <= picked.vdeadline <= vdeadline_i` for every still-queued
`i`.

That argument is sound **only for tasks already queued when the pick ran**. A
task enqueued *afterwards* with sleeper credit is placed below the floor by
construction, so its deadline can be below `min_vruntime` and the original F2
is simply false. The draft did not notice because it never wrote out the scan
and the placement in the same place.

F2 is therefore restated as what the code actually maintains, which is the
property the wheel needs:

> `min_vruntime` is monotone non-decreasing, and every queued entry sits in
> `[bucket_of(min_vruntime), bucket_of(min_vruntime + HORIZON_VNS))` along the
> forward rotation from the cursor.

Monotonicity is the `if v > floor` guard in `pick_locked`. Membership of the
window is `bucket_index_checked`'s two clamps: below the floor collapses to the
cursor bucket (first in scan order, which is what credit is *for*), above the
horizon clamps and counts. Together the live window spans strictly less than one
revolution, which is F3, and an entry can never be mistaken for one a full lap
away.

The practical consequence for a reviewer: **the scan order is
"cursor-first, forward", not "numerically smallest deadline"**, and those
coincide exactly when every entry is at or above the floor. The clamp is what
makes the two agree in the one case where they otherwise would not.

```rust
/// Weighted-fair scheduling state.
///
/// Atomic because the charge runs on the CPU the task last ran on while a
/// peer's steal or `unschedule_task` reads the queue slot. `Relaxed`
/// throughout: ordering with the placement word is already supplied by
/// `sched_placement`'s Release/Acquire, and these fields are meaningless
/// without a placement to interpret them against.
#[repr(C)]
pub struct SchedEntity {
    vruntime: AtomicU64,
    /// `SchedWeight` exponent. Never zero: `init_invalid` writes the Normal
    /// exponent explicitly, in the same way `controlling_tty` and
    /// `fpu_last_cpu` are written, because all-zero is not this field's valid
    /// neutral value.
    weight_shift: AtomicU8,
    /// Slice granted at the last dispatch, in nanoseconds.
    slice_ns: AtomicU32,
    /// `(cpu << 16) | bucket`, or `SLOT_NONE`. Written under the owning
    /// queue's `queue_lock` immediately before the link and cleared after the
    /// unlink, so it is exact for whichever queue holds the task and
    /// stale-but-harmless for every other CPU, which refuses the removal on
    /// the cpu mismatch — the same answer they give today for a task queued
    /// elsewhere.
    queue_slot: AtomicU32,
    /// Repairs performed by `weight_shift()`. A non-zero value means the
    /// field was corrupt; surfaced by the `sched` kconsole line so it is not
    /// silent.
    weight_repaired: AtomicU32,
}

impl SchedEntity {
    pub const SLOT_NONE: u32 = u32::MAX;

    pub const fn new() -> Self {
        Self {
            vruntime: AtomicU64::new(0),
            weight_shift: AtomicU8::new(NORMAL_WEIGHT_SHIFT),
            slice_ns: AtomicU32::new(0),
            queue_slot: AtomicU32::new(Self::SLOT_NONE),
            weight_repaired: AtomicU32::new(0),
        }
    }

    /// Never returns a zero exponent: a zero read is repaired to the Normal
    /// exponent and counted, so a corrupted field degrades to Normal service
    /// rather than making `SchedWeight::scale` a no-op and the virtual clock
    /// a lie.
    pub fn weight_shift(&self) -> u8 {
        let s = self.weight_shift.load(Ordering::Relaxed);
        if s == 0 {
            self.weight_repaired.fetch_add(1, Ordering::Relaxed);
            self.weight_shift.store(NORMAL_WEIGHT_SHIFT, Ordering::Relaxed);
            return NORMAL_WEIGHT_SHIFT;
        }
        s
    }

    pub fn queue_slot(&self) -> Option<(u8, u16)> {
        let raw = self.queue_slot.load(Ordering::Relaxed);
        if raw == Self::SLOT_NONE {
            return None;
        }
        Some(((raw >> 16) as u8, (raw & 0xffff) as u16))
    }

    pub fn set_queue_slot(&self, cpu: u8, bucket: u16) {
        self.queue_slot
            .store(((cpu as u32) << 16) | bucket as u32, Ordering::Relaxed);
    }

    pub fn clear_queue_slot(&self) {
        self.queue_slot.store(Self::SLOT_NONE, Ordering::Relaxed);
    }

    // vruntime / set_vruntime / set_weight_shift / slice_ns / set_slice_ns /
    // weight_repaired: one-line Relaxed load or store each.
}
```

```rust
    throttled_periods: AtomicU32,
    /// Periods in which the budget was spent but band B was empty, so nothing
    /// was throttled. Non-zero here is healthy: it is the corrected throttle
    /// working, not a fault.
    unthrottled_periods: AtomicU32,
    /// Task id that consumed the budget, for the klog line. `INVALID_TASK_ID`
    /// when the period was not exhausted.
    culprit: AtomicU32,
}

/// 100 ticks at a 10 ms LAPIC period = 1 s, the same period as the documented
/// RT-bandwidth default.
const RT_PERIOD_TICKS: u32 = 100;
/// 95 of every 100 ticks — the same 95 % ratio as that documented default. The
/// reserved 5 % is what leaves a runaway privileged task recoverable rather
/// than fatal.
const RT_QUOTA_TICKS: u32 = 95;
const _: () = assert!(RT_QUOTA_TICKS < RT_PERIOD_TICKS);
```

```rust
impl RtBudget {
    /// One tick of period time, plus one tick of budget if band A ran.
    ///
    /// `fetch_sub` on a saturating floor rather than a CAS loop: a lost
    /// decrement under contention would cost at most one tick of quota, and
    /// there is only one writer per CPU anyway (its own timer ISR). The
    /// refill is the one CAS, and it is uncontended for the same reason.
    fn tick(&self, current_is_rt: bool) {
        if current_is_rt {
            let r = self.remaining.load(Ordering::Relaxed);
            if r > 0 {
                self.remaining.store(r - 1, Ordering::Relaxed);
            }
        }
        let left = self.period_left.load(Ordering::Relaxed);
        if left > 1 {
            self.period_left.store(left - 1, Ordering::Relaxed);
            return;
        }
        self.remaining.store(RT_QUOTA_TICKS, Ordering::Relaxed);
        self.period_left.store(RT_PERIOD_TICKS, Ordering::Relaxed);
        self.culprit.store(INVALID_TASK_ID, Ordering::Relaxed);
    }

    #[inline]
    fn is_exhausted(&self) -> bool {
        self.remaining.load(Ordering::Relaxed) == 0
    }

    fn reset(&self) {
        self.remaining.store(RT_QUOTA_TICKS, Ordering::Relaxed);
        self.period_left.store(RT_PERIOD_TICKS, Ordering::Relaxed);
        self.throttled_periods.store(0, Ordering::Relaxed);
        self.unthrottled_periods.store(0, Ordering::Relaxed);
        self.culprit.store(INVALID_TASK_ID, Ordering::Relaxed);
    }
}
```

Rules, in order:

1. `rt_budget_tick` is called once per timer tick from `scheduler_timer_tick`,
   decrementing `period_left`; at zero it refills.
2. A tick consumed by a band-A task decrements `remaining` (saturating).
3. `throttled = remaining == 0 && !fair.is_empty()`. **The second conjunct is
   not optional.** Without it this reproduces the force-the-CPU-idle defect
   upstream spent years undoing (§2), and the third arm of `dequeue_next` is
   the other half of the same correction.
4. Throttling is per-CPU and never migrates a task; a throttled band-A task
   stays queued and is picked the moment either the budget refills or band B
   drains.
5. Entering the throttled state klogs once per period at `klog_warn`, naming
   the culprit id. A silent throttle is a debugging trap. Once per period is
   at most one line per second per CPU, which is inside the klog rate the boot
   log already tolerates.

**Why the budget is not charged from the switch path.** The obvious
alternative is to charge `remaining` from the same TSC delta the fair band
uses. It is rejected because the budget is a *bound on precedence*, and a
band-A task that never switches out is exactly the case the bound exists for —
charging on switch-out would give a spinning `High` task an infinite budget.
The tick is the only clock that observes it.

- **`sched/src/scheduler.rs:483` `newcomer_outranks_current` — no change, and
  the reviewer's implied objection is rebutted here.**

  The first draft proposed a new preemption rule table. That was wrong, and the
  code says why. The comparison is:

  ```rust

      new.priority.as_u8() < slopos_arch::pcr::current_task_priority_for(cpu)

  ```

  It reads the `TaskPriority` byte the PCR publishes (`scheduler.rs:203-207`
  via `published_priority`, `:474`). Under this design `TaskPriority` is
  **unchanged** — the ABI, the repr values and the publication are all
  untouched (§5.8, authority) — so the comparison keeps meaning exactly what it
  means today, and it already produces the right answers for the new bands:

  | newcomer | current | `<` says | wanted | agrees? |
  |---|---|---|---|---|
  | `High` (0) | `Normal` (2) | preempt | preempt (band A over band B) | yes |
  | `KernelIo` (1) | `Low` (3) | preempt | preempt | yes |
  | `Normal` (2) | `Normal` (2) | **no** | no — the tick handles band B | yes |
  | `Low` (3) | `Normal` (2) | **no** | no | yes |
  | `Normal` (2) | `Low` (3) | preempt | **debatable** | see below |
  | anything | `Idle` (4) | preempt | preempt | yes |
  | anything | `PRIORITY_NONE` (255) | preempt | preempt | yes |

  Only one row is arguable: a waking `Normal` preempts a running `Low`
  immediately rather than waiting for the tick. That is *more* responsive than
  the fair band strictly requires and costs at most one context switch per
  wake, and it is the behaviour the tree has today. `test_newcomer_outranks_current_preemption_gate`
  (`sched_tests.rs:5827`) pins all of these rows already, including the
  equal-priority case it calls out as "the case that matters". **Changing this
  function would break an existing passing test to no benefit.** The draft's
  table is withdrawn; the function is untouched and the existing test is the
  evidence that it stays correct.

- **`sched/src/task/task_stats.rs:24` `task_record_context_switch`** — the
  accounting hook, on a delta the tree already computes:

  ```rust

      let last = from.last_run_timestamp();

          from.add_total_runtime(delta);
  ```

  **`ticks_to_nanoseconds` is a new function** in
  `kernel-services/src/clock.rs`, beside `ticks_to_microseconds` (`:45`). It
  cannot reuse that one: microsecond resolution against a 10 ms tick is fine,
  but the *`u128` multiply-and-divide* it performs (`clock.rs:48`) is a
  `__udivti3`-class call, and putting it on every context switch is both a cost
  and a thing `check_kernel_softfloat.sh` has to keep tolerating. The new
  function is a `u64` reciprocal:

  ```rust
  /// TSC cycles -> nanoseconds, in `u64` only. `ns_per_tick_q32` is
  /// `(1e9 << 32) / freq_hz` computed once at cache time, so the hot path is
  /// one 64x64 multiply-high and one shift. Returns 0 before the platform
  /// clock is up, exactly as `ticks_to_microseconds` does.
  pub fn ticks_to_nanoseconds(ticks: u64) -> u64;
  ```

  The multiply-high is `u64::widening_mul`-shaped; if that is unstable on the
  pinned nightly, the fallback is `(ticks >> 10) * ns_per_1024_ticks`, which
  loses ~0.1 % accuracy and is entirely acceptable for a fairness clock. Either
  way, **no `u128`, no builtin division, no vector register.**

- **`sched/src/scheduler.rs:1762` `scheduler_timer_tick`** — one call, placed

  `per_cpu::init_all_percpu_schedulers` (`:1679`), whose first statement is

  `SchedulersInitFlag` hermetic block (`test_hermetic.rs:81-98`) *restores* the
  flag to set on scope exit, precisely so the flag looks untouched — with the
  documented consequence, in its own comment at `:79-80`, that without a Drop

  What actually runs on every scope boundary is `KernelTestScope::drop`
  (`test_fixture.rs:197`) → `clear_all_cpu_queues()` (`:201`) →

  a floor already advanced by the first, and `place_vruntime` would clamp its
  tasks into a band the test did not construct. Test 14 is the gate on this,
  and it now has a real failure mode rather than a hypothetical one.

### 5.7 Failure paths

| Condition | Response |
|---|---|
| `SchedWeight::from_shift` rejects a stored exponent | `weight_of` falls back to `SchedWeight::NORMAL`. The task gets Normal service; nothing panics on the dispatch path. |
| `SchedEntity::weight_shift()` reads zero | repair to `NORMAL_WEIGHT_SHIFT`, bump `weight_repaired`, return the repaired value. A zero would make `scale` an identity and the virtual clock a lie. |
| `SchedWeight::for_priority` returns `None` (band A/C task reaching band B code) | unreachable through `band_of`, which is exhaustive; `weight_of` still answers Normal. `debug_assert!(false)` in the fair path, count, continue. |
| `delta_ns > MAX_CHARGE_NS` (TSC lied, VM exit, migration on a non-invariant TSC) | `SchedWeight::scale` clamps to `MAX_CHARGE_NS`; `FairQueue::charge` bumps `charge_clamped`. A clamp loses fairness for one switch; trusting the value loses the virtual clock permanently. Test 11. |
| `ticks_to_nanoseconds` returns 0 (platform clock not up yet) | the charge is a no-op for that switch. Correct: before the clock exists there is no fair time to divide, and every task is equally uncharged. |
| Computed bucket beyond the horizon | `bucket_index_checked` clamps to the last bucket inside the horizon, bumps `bucket_clamped`, `debug_assert`s. F3 says this is unreachable; the counter is how we learn it became reachable. Test 5. |
| Enqueue `vruntime` outside the band | `place_vruntime` clamps to the band edge; the high side bumps `band_clamped`. Forgiving excess debt is a fairness loss for one task; letting it index past the horizon is a wrong pick for everyone. |
| `vdeadline` below `min_vruntime` (a credited sleeper) | **not** a failure — `bucket_index_checked` returns the cursor bucket, which is first in scan order. Counted by nothing, because it is the credit mechanism working. Test 13's second half is what distinguishes this from the wrap case. |
| `link_locked` gets `LinkError::AlreadyLinked` | return `1` exactly as today ("some queue already owns it") **and roll the `queue_slot` stamp back**, so F5 holds. The publish fallback (`scheduler.rs:487-500`) distinguishes 0/1/-1 and must keep seeing all three. |
| `link_locked` gets `LinkError::NotPresent` | return `-1`, roll the stamp back. `enqueue_local_from_placement` (`per_cpu.rs:298`) maps this to its own `-1`, which is what stops a never-published task from being treated as published. |
| `remove_locked` finds `SLOT_NONE` or a foreign cpu | return `-1` (`NotPresent`) — today's answer for a task queued on another CPU, and the answer 255 of 256 CPUs give on every `unschedule_task`. | `occupancy` disagrees with the buckets | `repair_occupancy` rebuilds the bitmap from 32 `is_empty` loads, bumps `occupancy_repaired`, `debug_assert`s, and the pick retries once. A pick that returned `None` on a non-empty queue would strand every task on that CPU. Test 15. |
| Band A budget underflow | guarded load-then-store on a zero floor; a negative budget is not representable in `AtomicU32`. |
| `with_cpu_scheduler` returns `None` in `reset_task_quantum` | fall back to `SCHED_DEFAULT_TIME_SLICE`. A zero slice would disable preemption for that task, which is the failure this fix exists to prevent. |
| `slice_ticks_for` computes 0 (period smaller than a tick) | `.max(1)`. The `MIN_GRANULARITY_NS == TICK_NS` const assert makes this unreachable; the `max` is the belt. |

### 5.8 Interaction with existing subsystems

- **TLB shootdown.** No interaction. Selection touches no page table and takes
  no mm lock. The `while next_task.on_cpu() { spin_relax() }` wait in
  `run_ready_task_from_idle` (`scheduler.rs:1023-1026`), which services
  cross-CPU shootdowns by hand, is unchanged, and the fair pick runs *before*
  it exactly as the priority pick does today. The property to preserve is
  precise, and it is why `dequeue_next` takes the lock internally rather than
  the caller holding it: `queue_lock` is a `cli` spinlock
  (`slopos-ostd/src/sync/spin.rs:417-429`), so holding it across the `on_cpu`
  spin would mean spinning with interrupts off while waiting for another CPU
  that may itself be blocked on a shootdown acknowledgement from *this* CPU — a
  deadlock, not a slowdown. `dequeue_next`'s guard is dropped at its own
  return, before `scheduler.rs:989` even assigns the result.
- **The `charge_fair_runtime` hook takes a lock the switch path did not.**
  `FairQueue::charge` is deliberately **not** `_locked`: it touches only the
  task's own atomics, and the task is off-queue at that moment (it just ran).
  So `task_record_context_switch` acquires nothing new, and the context-switch
  path's lock profile is unchanged. This is load-bearing for lockdep: the
  switch path runs with IRQs off inside `run_switch`, and adding
  `LOCK_LEVEL_SCHEDULER` there would create an ordering edge against every lock
  already held across a switch.
- **Quota accounting.** Nothing is allocated on any path in §5 — no `KBox`,
  `KVec`, `KArc` or `KBTreeMap` appears — so no quota account is charged and no
  new account kind is introduced. `scripts/gates/quota/tests.txt` records peaks
  per `<phase, kind>`; the *kinds* cannot change, but the *peaks* can, because
  they track the live population the userland phase reaches and this change
  alters the interleaving that produces it. Re-measure from the same
  `builddir/ci-test.log` capture as the other two ratchets (§6), and expect the
  `task` and `kernelmeta` rows to move by a small amount in either direction.
  A *large* move is a review flag that something started allocating.
- **Lockdep.** The fair queue lives under the existing
  `PriorityRunQueue.queue_lock` (`per_cpu.rs:161`, class declared at `:182-185`
  at `LOCK_LEVEL_SCHEDULER`) and the budget is lock-free, so **no class and no
  edge are added by construction**. This is a design constraint, not an
  accident: the alternative — a second lock for the wheel — would order the
  scheduler under itself, and `lock_nested` with a subclass is the only honest
  way to express that, which would be a *new* class in the gate's accounting
  either way. Three specific things preserve the property, and a reviewer
  should check each: (a) `FairQueue`'s mutating methods are all `_locked` and
  take no lock themselves; (b) `RtBudget` uses plain atomics only, so
  `rt_budget_tick` from the timer ISR takes nothing; (c) `charge` is lock-free,
  so the context-switch path is unchanged. Class caps in
  `scripts/gates/lockdep/tests.txt` should hold **exactly**, and a class-count
  move is a signal the design was not followed. Edge and chain counts *will*
  move, since they track interleaving; those caps carry measured spread and
  must be re-measured with `--emit-allowlist` over several runs, not one.
- **Authority model.** No new syscall, no new handler, no new capability, no new
  edge toward a power primitive. `TaskPriority` remains the ABI it is and the
  syscall boundary keeps rejecting everything but `Normal`/`Low`.
  `scripts/gates/authority/*.txt` should be byte-identical.
- **Task-ownership discipline (I1–I8).** No raw task pointer is introduced:
  `FairQueue` holds `ReadyQueue`s, which hold an `IntrusiveLinkedList<Task,
  ReadyQueueRole>` — the sanctioned surface — and every hand-off is a `TaskRef`
  or a `&Task`. `queue_slot` stores a *(cpu, bucket)* pair, not an address, so
  it is not a designator that can be dereferenced. `scripts/check_task_ownership.sh`
  should be unaffected; if it fires, the code diverged from this document.
- **Process-designator discipline.** `queue_slot` is keyed on CPU index and
  bucket index, both bounded and both non-recycling. No `u32` pid appears
  anywhere in §5, so `check_process_designator.sh` has nothing to see.
- **Verus.** `verification/proofs/task_ownership.rs` models the retain/reclaim
  protocol and the `SchedPlacement` transitions. Neither changes: the fair queue
  reuses the same link slot, the same `task_placement_retain`, the same
  `TaskRef::from_placement`, and adds no placement variant.
  `task_is_dispatch_pinned` is untouched — `verification/STATUS.md`'s header
  asks to be read before changing it, and this design does not. The model still
  describes the tree; re-run `just verify` anyway.
- **KernMiri.** The ostd change is a plain struct field and safe accessors, so
  `just check-miri` should be unaffected. Run it, since ostd is touched.
- **`.bss` cost.** `ReadyQueue` is 24 bytes (`AtomicPtr` head + `AtomicPtr`
  tail + `AtomicUsize` count, `slopos-ostd/src/sync/intrusive.rs:143-151`).
  Today: `5 × 24 = 120 B` per CPU. After: `2 × 24` (band A) `+ 32 × 24` (wheel)
  `+ 24` (band C) `= 840 B`, plus 36 B of `FairQueue` scalars and 20 B of
  `RtBudget`, rounded up by the struct's `align(64)` — about **+780 B per CPU**.
  `MAX_CPUS = 256` (`slopos-ostd/src/cpu/x86_64/pcr.rs:17`), so **≈ +195 KiB of
  `.bss`**. That is the price of an O(1) ordered pick without a tree, and it is
  paid in `.bss` rather than in the TCB, which is the trade this design prefers
  everywhere. If it is judged too much, `NBUCKETS = 16` halves the wheel but
  halves `HORIZON_VNS` to 67 ms, which no longer admits
  `ENQUEUE_BAND_VNS + MAX_VSLICE_VNS = 96 ms` — so both of those constants must
  come down with it. The const assert makes that a build failure rather than a
  silent correctness loss, which is exactly the property §5.1.2 was rewritten to
  obtain.
- **`Task` size.** `SchedEntity` is 24 B on a struct the razor at
  `sched/src/task_struct.rs:69` caps at 8192 B. `Task` is allocated one per
  task from the heap, so this is 24 B × live tasks, not × `MAX_TASKS`. The
  razor is a `const _`, so an overflow fails the build.

hangs until the deadline and fails.** It is the only test in the set that

## 8. Residual risk this fix does **not** close

Stated plainly, because a fix proposal that claims to close everything is not
reviewable.

1. **No EEVDF eligibility test ⇒ no lateness bound.** §3 cuts this deliberately.
   Starvation is closed (every task's position improves monotonically while it
   waits), but the published EEVDF guarantee — service within one quantum of
   entitlement — is *not* obtained. A newly-woken task can wait up to the sum of
   the queued slices. With `TARGET_LATENCY_NS = 60 ms` that is bounded and
   small, but it is a weaker bound than the literature offers, and closing it
   needs an augmented ordered tree in `slopos-ostd`, i.e. new `unsafe` in the
   TCB.
1b. **The wheel's resolution is 4.19 ms, so ordering inside a bucket is FIFO,
   not by deadline.** Two tasks whose virtual deadlines differ by less than one
   bucket may run in the wrong order relative to each other. The error is
   bounded by `1 << BUCKET_SHIFT` and is smaller than the minimum slice
   (10 ms), so it cannot accumulate into a share error — the `vruntime` charge
   is exact regardless of pick order. It is nonetheless a real deviation from
   the ordered-tree formulation and is the price of O(1) selection with no new
   `unsafe`. Test 7 pins the FIFO behaviour so the deviation is *stated* rather
   than discovered.
2. **`High` can still starve `KernelIo`.** Band A is internally strict priority,
   so a runaway `High` task starves `KernelIo` for up to the whole quota window
   (95 ticks ≈ 950 ms) before band B — not `KernelIo` — is what gets the reserve.
   Exposure is bounded: `High` is conferred to exactly one program by identity
   (`/bin/compositor`), so this is a compositor bug, not an unprivileged attack.
   The fix would be a per-tier sub-budget inside band A; it is not proposed here
   because there is no evidence it is needed.
3. **No cross-CPU fairness.** The virtual timeline is per-CPU. A task pinned by
   `set_cpu_affinity` to a loaded CPU receives strictly less service than an
   unpinned peer on an idle one, and work stealing is opportunistic (3-tick
   cooldown, imbalance ≥ 2, victim queue length > 1). An unprivileged caller can
   still concentrate load by pinning. Closing this needs periodic load balancing
   against a global fair-share target, which is a separate, larger change.
4. **`TASK_FLAG_NO_PREEMPT` is outside the mechanism.** `scheduler_timer_tick`
   returns early for such a task (`scheduler.rs:1836`), so neither the fair
   slice nor the band-A budget can reclaim from it. No spawn path grants that
   flag (`SPAWN_PRIVILEGED` refuses it at the syscall boundary), so today this is
   kernel-internal only — but it is an unbounded hole for any future code that
   sets it.
5. **A kernel loop that reaches no blocking primitive is still unstoppable.**
   This is `AGENTS.md`'s own stated I8 residual and is unaffected: selection
   cannot preempt what the tick refuses to preempt.
6. **TSC trust.** Virtual time is charged from TSC deltas measured between
   switch-in and switch-out on one CPU, so cross-core TSC skew does not enter the
   comparison — but a non-invariant TSC that changes rate *within* a slice
   mis-charges that slice. Clamped (`MAX_CHARGE_NS`) and counted, not corrected.
   Under QEMU/TCG this is expected to fire occasionally; a *rising*
   `charge_clamped` on real hardware means the clock source needs revisiting.
7. **The constants are still choices.** `TARGET_LATENCY_NS`,
   `MIN_GRANULARITY_NS`, `MAX_SLICE_NS`, `MAX_VSLICE_VNS`, `ENQUEUE_BAND_VNS`,
   `NBUCKETS`, `BUCKET_SHIFT`, the 16:1 `Normal:Low` ratio and the 95 % quota
   are engineering choices, not measurements. They are *defensible* choices
   with published analogues, they are named constants under const-asserts that
   catch incoherent combinations at build time, and changing one is a diff on a
   tracked line — strictly better than a magic `N` inside a scan. It is not the
   same as having measured them on this kernel's workloads. The revision-2
   rewrite of §5.1.2 is the evidence for why this matters: the first draft's
   `MAX_VDEADLINE_OFFSET_VNS` was *derived* rather than chosen, and its
   correctness depended on `MAX_SLICE_NS` staying at a value the same document
   later had to change.
8. **Denial of service by task count is untouched.** `MAX_TASKS = 8192` and the
   per-process task quota bound how many entities compete; a fair scheduler
   divides the CPU fairly among 8192 tasks, which is fair and also unusable. That
   is a quota question, not a scheduling one.
9. **This is a policy change to the most timing-sensitive code in the kernel.**
   The honest risk of the change itself is regression: a wrong `min_vruntime`
   advance or a wheel-wrap bug is a hang, not a wrong number. The mitigations are
   the const assertions (build-time), F2/F3 (one-paragraph proofs a reviewer can
   check), the `debug_assert`s and counters (test-kernel), and test 8's refcount
   balance check (the leak class). It remains the riskiest part of the proposal
   and should land as its own commit with the full pre-commit sequence run.
10. **The `Task` size razor is a hard ceiling this change moves toward.**
   `sched/src/task_struct.rs:69` caps `size_of::<Task>()` at 8192 B and
   `SchedEntity` spends 24 of whatever remains. The landing commit for §5.2
   must report the before/after size in its message, because the next feature
   to add a `Task` field deserves to know how much room is left.
11. **Nothing here bounds a task that never yields *and* never ticks.** The
   band-A budget is charged by the timer tick; a `High` task that runs with
   interrupts disabled accrues no charge and is throttled by nothing. That is
   the same residual as item 5 and is stated separately only because the budget
   might otherwise be read as covering it.

## 9. Suggested landing order

Each step builds and tests green on its own.

1. **`kernel-services`: `ticks_to_nanoseconds`.** One `u64` function beside
   `ticks_to_microseconds` (`clock.rs:45`), with a host-side unit test for the
   reciprocal. Nothing calls it yet. Isolated first because it is the only
   change with a numerical-accuracy question and it should not be debugged
   alongside a scheduler rewrite.
2. **`slopos-ostd`: `SchedEntity`** + the four construction/reset sites
   (`invalid` :1123, `init_invalid` :1217, `reset_runtime_state` :1404,
   `clone_from_raw` :1440), plus `NORMAL_WEIGHT_SHIFT`. No behaviour change: the
   field is written and never read. Report the `size_of::<Task>()` delta in the
   commit message (§8 item 10). Run `just check-miri` and `just verify` — this
   is the only commit that touches `slopos-ostd/` and `AGENTS.md` puts both in
   scope for it.
3. **`ReadyQueue` visibility.** Mechanical `pub(crate)` on the eight methods
   §5.1 lists, no body changes. Separate so the diff that *moves* scheduling
   policy contains no mechanical noise.
4. **`sched/src/fair.rs`:** `SchedWeight`, the constants, every const assertion,
   `FairQueue`. Unreferenced by the dispatcher, so this cannot regress boot.
   Tests 5, 7, 10, 11, 13, 16 land here.
5. **`per_cpu.rs`:** the three-band `PriorityRunQueue`, `band_of`,
   `dequeue_next`, the band-aware enqueue/remove/steal/count, the `init` and
   **`clear_cpu_queues`** resets, and the `scheduler.rs:989` call-site swap.
   Tests 1, 6, 8, 9, 14, 15. **This is the commit that closes the finding**, and
   the one to bisect to if scheduling regresses.
6. **The accounting hook** in `task_stats.rs` and `reset_task_quantum` in
   `scheduler.rs`. Tests 2 and 12 — note test 2 cannot pass before this step,
   because without the charge every `vruntime` stays zero and share is
   unmeasurable.
7. **`RtBudget` + the tick hook.** Tests 3, 4.
8. **The `sched` kconsole lines, the userland test, and all gate
   re-measurements** in one commit with each delta explained. The re-measurement
   sequence is `AGENTS.md`'s: one `builddir/run_tests --raw --no-color` capture
   feeding `check_test_count.sh`, `check_lockdep_headroom.sh` and
   `check_quota_headroom.sh` via `--log`, never three boots.

Do not collapse 5 and 7: the fair band and the budget fail differently — a fair
bug is a wrong share, a budget bug is an unresponsive machine — and a bisect
wants them apart. Do not collapse 5 and 6 either: step 5 leaves the fair band
correct but uncharged, which is a *legible* intermediate state (round-robin
within band B) rather than a broken one, and it is the state that isolates a
charge bug from a selection bug.

Every commit in the sequence runs the full `AGENTS.md` pre-commit sequence —
`cargo fmt --all`, `just fmt`, `just test-host`, `just build`,
`just check-framekernel-gates`, then the captured test run and the three
ratchets — and takes its message from the `caveman-commit` skill.
