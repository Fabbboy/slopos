# SLOPOS-2026-0016 — AF_UNIX SCM_RIGHTS has no cycle policy

**Proposal only. No repository file outside this document is modified.**

Status: design proposal, ready to implement without further design work.
Scope: `abi/`, `fs/`, `net/`, `core/`, plus a one-line `containment()` answer in
each of the 13 crates that implement `FileOps` (`core`, `drivers`, `fs`, `mm`,
`net`, `ring`, `pidfd`, `signalfd`). No `slopos-ostd` change, therefore **no new
`unsafe` anywhere** — see §9.

## 1. Evidence: what the tree actually says

Every path below was read at proposal time. The ledger is corrected where wrong.

### 1.1 The teardown edge (ledger said `unix_socket_file_ops.rs:26-30`)

`net/src/unix_socket_file_ops.rs:20-34` — the real span is **:30-34**:

```rust

#[derive(slopos_ostd::Charged)]
struct UnixSocketBacking {
    handle: SocketHandle,
    object_charge: Charge<ObjectRow>,

...
impl Drop for UnixSocketBacking {
    fn drop(&mut self) {
```

`UnixSocketBacking` is stored as `OpenFile::backing`
(`fs/src/fileio/mod.rs:164-167`), so the AF_UNIX slot is released **only** when
the last `KArc<OpenFile>` alias of that description drops. That is the retention
edge the whole finding hangs on.

second way to reach it.

### 1.4 The ancillary queue holds owning aliases (ledger said `pair.rs:46-65`)

Correct in substance; the type is `net/src/unix_socket/pair.rs:42-44`, entries
at **:54-58**, `push` at **:74-94**, `drain` at **:103-105**:

```rust

43:     entries: KVec<InFlightFile>,
44: }
55: pub(super) struct InFlightFile {
56:     pub(super) file: FileRef,
57:     #[expect(dead_code, reason = "held for ownership; dropping it is the refund")]
```

`AncillaryQueue` lives on `ConnectionPair` (`pair.rs:115-123`), **two per pair,
one per direction**, and the pair is only detached from `PairTable` when its
`refcount` reaches 0 (`pair.rs:224-238`, `PairTable::release`).

### 1.5 The caps (ledger said `MAX_UNIX_SOCKETS = 32`)

**Wrong.** `abi/src/event.rs:11`:

```rust
pub const MAX_UNIX_SOCKETS: usize = 128;
```

and therefore `net/src/unix_socket/pair.rs:24`, `MAX_UNIX_PAIRS = 64`;
`pair.rs:20`, `MAX_INFLIGHT_FDS = 8` per direction;
`abi/src/syscall/posix.rs:111`, `SCM_MAX_FDS = 4` per `sendmsg`.
Per-account `Custody` default ceiling is 64 (`abi/src/quota.rs:163`).

The corrected numbers make the DoS *cheaper to reach in absolute terms* than the
ledger implies per-socket, and no less permanent: 128 slots, 64 pairs, and each
pair pins two 16 KiB `KVecDeque` FIFOs (`net/src/unix_socket/buffer.rs:9,20-24`)
— **2 MiB of unreclaimable kernel heap** at full exhaustion, plus every in-flight
`FileRef`'s own backing (a leaked memfd pins its pages).

### 1.6 "In-flight fds are also not reclaimed on process exit" — correct, and
sharper than stated

Process exit drops the fd table, which drops each `FdEntry`'s `KArc<OpenFile>`.
For an ordinary in-flight descriptor that is enough: the queue's alias is the
last one only if nothing else holds it, and when both endpoints eventually close,
`PairTable::release` returns the pair and `unix_close` drops it off-lock
(`mod.rs:769-812`). The leak is **not** the general case; it is precisely the
case where the description held by an ancillary queue is *itself* an AF_UNIX
endpoint whose slot that queue transitively keeps alive.

### 1.7 The minimal deterministic repro — one socket, one `sendmsg`

The finding is titled "cycle policy", but this tree does not need two sockets to
close the loop. `unix_connect` (`mod.rs:191-285`) makes slots `a` and `b` sharing
one `ConnectionPair`. Then:

1. `sendmsg(fd_a, cmsg = [fd_a])` — the alias of `a`'s own description lands in
   the pair's `anc_a_to_b` queue (`mod.rs:532-542`).
2. `close(fd_b)` — `UnixSocketBacking(b)` drops, `unix_close(b)` removes slot
   `b` and calls `pairs.release(pair)`; refcount 2 → 1, so `release` returns
   `None` (`pair.rs:228-234`) and **the pair, with both queues, stays in the
   table**.
3. `close(fd_a)` — the fd table's alias drops, but the queue still holds one.
   `KArc<OpenFile>` strong count is still ≥ 1, so `UnixSocketBacking(a)` **never
   drops**, so `unix_close(a)` **never runs**, so slot `a` is never removed and
   the pair refcount is stuck at 1 forever.

Note which layer kills this repro, since it bears on §4.2's narrowing: step 2
closes `b`, and `b` is the **receiver** of `anc_a_to_b`, so the corrected Layer B
empties that queue at step 2 and step 3's close then completes. Layer A refuses
the send at step 1 outright. Either layer alone closes *this* repro; both are
kept because Layer A also closes the two-socket cycle where the closes are
ordered so no purge fires first, and Layer B also closes the cycle-free
retention case in §3.3.

Net cost to the attacker: 3 syscalls. Net cost to the system: one AF_UNIX slot,
one pair, 32 KiB of FIFO, permanently. Repeat 64 times from one unprivileged
process and the *system-wide* AF_UNIX table is dead for every process until
reboot — including the compositor's socket
(`slop-protocol/src/connection.rs`), which is the tree's only IPC transport.

The classical two-socket cycle (A's queue holds B, B's queue holds A) is a strict
superset and leaks the same way. The `Custody` charge does not save us: it is the
*sender's* charge and it is refunded when the queue drops, which is exactly what
never happens.

## 2. Prior art, and what mature kernels actually settled on

### 2.1 Linux: 20 years of GC, and the direction of travel is *away* from it

`net/unix/garbage.c` has existed since 2.6.12 (2005) and the file's own change
log records the shape of the problem: Al Viro's 1998 notes on cycles and on
`fput()` blocking mid-sweep; Miklos Szeredi's 2007 "Reimplement with a cycle
collecting algorithm ... solve several problems with the previous code, like
being racy wrt receive and holding up unrelated socket operations".

The mark-and-sweep era produced a steady stream of defects, verifiable from the
public log: *"net: Fix soft lockups/OOM issues w/ unix garbage collector"*
(2008-11-26), *"net: unix: fix inflight counting bug in garbage collector"*
(2008-11-09), *"net: unix: properly re-increment inflight counter of GC
discarded candidates"* (2017-03-21), *"af_unix: Fix task hung while purging
oob_skb in GC"* (2024-02-13).

Two orthogonal bounds were bolted on because the GC could not be made cheap:

- **Recursion depth**, commit `25888e30319f` (2010-11-25, Eric Dumazet), whose
  message is explicit that this is a resource bound and not a correctness fix:
  *"Its easy to eat all kernel memory and trigger NMI watchdog, using an exploit
  program that queues unix sockets on top of others ... one choice we have is to
  have a recursion limit."* Limit: 4.
- **Per-user in-flight accounting**, commit `712f4aad406b` (2016-01-10, Willy
  Tarreau), *"Mitigates: CVE-2013-4312"*: *"It is possible for a process to
  allocate and accumulate far more FDs than the process' limit by sending them
  over a unix socket then closing them to keep the process' fd count low."*
  SlopOS already has this as the `Custody` axis — that part of the class is
  **already closed here** (`pair.rs:54-94`, `abi/src/quota.rs:163`).

The 2024 rewrite (`4090fa373f0e`, Kuniyuki Iwashima, merged 2024-03-29) replaced
238 lines of mark-and-sweep with Tarjan's SCC algorithm over an explicit
`unix_vertex`/`unix_edge` graph maintained at queue/dequeue time, collecting only
*dead* SCCs. It is materially better, and it is still not finished: after the
rewrite landed, the same file took `af_unix: Fix garbage collection of embryos
carrying OOB with SCM_RIGHTS` (2024-05-21), `af_unix: Don't access successor in
unix_del_edges() during GC` (2024-04-23), `af_unix: Fix uninit-value in
__unix_walk_scc()` (2024-07-03), and as recently as 2026-03-12 `af_unix: Give up
GC if MSG_PEEK intervened` — which adds a seqcount so the collector *aborts and
retries* when a concurrent `MSG_PEEK` moves a reference the walk already counted.
The current tree also carries `unix_schedule_gc`, which refuses to even queue the
work unless the sending user is over `SCM_MAX_FD * 8` in-flight — i.e. the GC is
now hidden behind the same accounting bound that was supposed to be its backstop.

**Read of Linux, for our purposes:** a general cycle collector over a *concurrent,
mutable* object graph is a permanent maintenance liability. Linux pays it because
it cannot break the ABI: `SCM_RIGHTS` of an `AF_UNIX` socket is load-bearing for
`systemd`, X11, D-Bus and Wayland.

### 2.2 io_uring: the settled answer was refusal

io_uring registered files could form cycles with `AF_UNIX` queues, so it grew
`unix_inflight` bookkeeping (`Add io_uring IO interface`, 2019-02-28), then
`io_uring/af_unix: defer registered files gc to io_uring release` (2022-10-12),
and finally gave up. Commit `705318a99a13` (2023-12-06, Pavel Begunkov,
reported-and-suggested-by Jann Horn), *"io_uring/af_unix: disable sending
io_uring over sockets"*:

> *"File reference cycles have caused lots of problems for io_uring in the past,
> and it still doesn't work exactly right and races with
> `unix_stream_read_generic()`. The safest fix would be to completely disallow
> sending io_uring files via sockets via SCM_RIGHT, so there are no possible
> cycles involving registered files and thus rendering SCM accounting on the
> io_uring side unnecessary."*

It is `Cc: stable`, and it returns `-EINVAL` at `scm_fp_copy`. The follow-up
`af_unix: Remove io_uring code for GC` (2024-01-31) then deleted the
corresponding machinery from `garbage.c` outright. This is the single most
relevant precedent in the whole history: a *new* subsystem, unencumbered by
legacy ABI, was allowed to declare itself un-passable, and the cycle class it
created disappeared along with the code that policed it.

### 2.3 Capability systems: the cycle is unrepresentable by construction

Zircon documents, for `zx_channel_write`, `ZX_ERR_NOT_SUPPORTED`: *"A handle to
the channel performing the write cannot be included in the handles array. In
other words a channel handle cannot be written to its own channel."* That is a
narrower rule than ours (it forbids only the direct self-loop), but the design
posture is the one worth copying: the kernel refuses the edge at the transfer
point rather than reclaiming it later.

### 2.4 Conclusion drawn for SlopOS

SlopOS has **no legacy ABI obligation to pass AF_UNIX sockets over SCM_RIGHTS.**
The only in-tree users of `SCM_RIGHTS` pass a **memfd**
(`userland/src/apps/terminal/mod.rs:635`,
`userland/src/apps/compositor/protocol.rs:482`,
`userland/src/syscall/wrappers/memfd_buf.rs:82`), and the userland transport
`slop-protocol/src/connection.rs:98-135` attaches exactly one fd per message.
`slibc` does not even implement `socketpair` (`slibc/std_pal/net/slopos.rs:361`).

So SlopOS is in io_uring's position in 2023, not Linux's in 2005 — and it should
take io_uring's answer, generalised and made structural, rather than Linux's.

## 3. The minimal patch, and why it is not enough

**Minimal patch (≈8 lines):** in `core/src/syscall/net_handlers.rs:641-643`,
after `fileio_clone_file_ref`, reject when the resolved ops report
`is_unix_socket()`.

It is insufficient on five counts:

1. **Wrong choke point.** *Revision 1 justified this by claiming the ring's send
   paths call `unix_sendmsg`. That was wrong and is retracted:*
   `ring/src/net_glue.rs:660-692` (`recvmsg_fixed`) and `:700-745`
   (`recvmsg_provided`) are receive-side and call `unix_recvmsg_into`
   (`net_glue.rs:679`, `:733`). The complete non-test caller set of
   `unix_sendmsg` today is `core/src/syscall/net_handlers.rs:644` and the
   in-module `unix_send` wrapper (`mod.rs:294`).

   The argument stands on different ground. `unix_sendmsg` is `pub` from
   `slopos_net`, takes `&mut KVec<FileRef>`, and its own doc comment
   (`mod.rs:478-484`) states the ownership contract for that vec — so the
   *contract* is the function's, and a predicate enforced two crates away in one
   `define_syscall!` body is a comment, not a constraint. The ring already
   handles AF_UNIX fds and already builds `KVec<FileRef>` (`net_glue.rs:277`);
   `ring/src/opcode.rs` has no `OP_SENDMSG`-with-cmsg arm *today*, and adding
   one is a natural next commit. If the predicate lives in the signature, that
   commit does not compile until it asks. That is the difference the type buys,
   and it is the whole argument — the ring is the *next* caller, not a current
   one.
2. **`is_unix_socket()` is not the predicate.** The hazard is "this description
   can hold `FileRef`s", and a ring does: `InFlight::file` is
   `Option<FileRef>` (`ring/src/ring_obj.rs:24`), populated from
   `fileio_clone_file_ref` at `ring/src/enter.rs:312-315` and moved in by
   `opcode::inflight_from` (`ring/src/opcode.rs:77-80`). `Ring` is
   `transferable == true` (`abi/src/file_ops.rs:63-77`). A ring fd passed over
   AF_UNIX, holding an in-flight `FileRef` to that same socket, is the io_uring
   cycle reproduced exactly. The minimal patch leaves it wide open.
3. **It leaves a second, cycle-independent retention bug.** *Revision 1 stated
   this too broadly — corrected here, and the correction is what reshapes Layer
   B (§4.2, R1).* When one endpoint closes, what was queued **toward the closing
   endpoint** becomes permanently undeliverable: `drain_ancillary` resolves a
   queue through the *receiver's* slot (`mod.rs:658-663`), and that slot is
   removed at `mod.rs:778`. Yet those `FileRef`s stay pinned until the *second*
   close releases the pair (`pair.rs:228-234`). A long-lived server that never
   closes its end pins a departed client's memfd pages indefinitely. That is a
   leak with no cycle in it.

   What revision 1 additionally claimed — that the *other* direction is also
   undeliverable — is false: the surviving peer's slot is still `Connected`
   (`mod.rs:783-791` marks `peer_closed` but does not remove it), so it can and
   should still drain what the departed endpoint sent it.
4. **It is not enforceable going forward.** Nothing makes a new `FileOps` impl
   declare whether its description may hold `FileRef`s. The next `Ring`-shaped
   subsystem silently reintroduces the class.
5. **It leaves the failure silent.** No counter, no console command, no test can
   see an AF_UNIX slot that has stopped being reclaimable.

**What the refactor buys over five years:** the cycle stops being a thing that
must be *detected* and becomes a thing that cannot be *constructed*. The cost is
paid once, in the type system, at the transfer boundary — no periodic scan, no
worker, no `gc_in_progress` flag, no lock-order edge from a collector to every
socket queue, and no 20-year tail of "the collector raced with X" commits, which
is demonstrably what the alternative costs.

## 4. The fix

Three layers. Layer A makes the cycle unrepresentable; Layer B removes the
retention edge that survives even without cycles; Layer C bounds and exposes what
is left.

### 4.1 Layer A — leaf-only ancillary transfer, enforced by a type

#### A1. Containment is a property of the **ops singleton**, not of `FileKind`

> **Review finding R6, rebutted.** The reviewer objected that keying containment
> on `FileKind` needlessly refuses AF_INET, since `FileKind::Socket` covers both
> families. That objection is *against a design revision 1 should not have
> proposed* — and the tree already contains the mechanism that makes it moot.
> `FileOps` is a per-family singleton: `net/src/socket_file_ops.rs:14` declares
> `SOCKET_FILE_OPS: SocketFileOps` for AF_INET and
> `net/src/unix_socket_file_ops.rs:17` declares
> `UNIX_SOCKET_FILE_OPS: UnixSocketFileOps` for AF_UNIX, both reporting
> `FileKind::Socket` but resolving to different vtables via
> `OpenFile::ops: &'static dyn FileOps` (`fs/src/fileio/mod.rs:156`). The trait
> already carries `is_unix_socket()` for exactly this reason, and says so:
> *"Distinguishes an `AF_UNIX` socket from an `AF_INET` one; both report
> [`FileKind::Socket`]"* (`abi/src/file_ops.rs:86-91`).
>
> So the predicate is a **trait method** and nothing else. The
> `file_kind_containment` free function of revision 1 is **deleted**, along with
> the `debug_assertions` cross-check that only existed to police the two
> statements against each other. There is one statement. AF_INET keeps passing
> over SCM_RIGHTS; the corresponding residual risk in §10 is withdrawn.

`abi/src/file_ops.rs`, beside `file_kind_transferable`:

```rust
/// Whether a description can itself own [`FileRef`]s.
///
/// A `Container` may participate in a reference cycle through any queue that
/// holds descriptions; a `Leaf` cannot, because it owns none.
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum FdContainment {
    Leaf,
    Container,
}
```

and on the `FileOps` trait, **with no default body**, so a newly written ops impl
does not compile until it answers:

```rust
    /// Whether this description owns `FileRef`s of its own.
    ///
    /// No default body on purpose: `Leaf` is the answer that admits a cycle if
    /// it is wrong, and a defaulted method is answered by silence. Per-ops
    /// rather than per-[`FileKind`] because two families share
    /// `FileKind::Socket` and only one of them owns a queue — the same reason
    /// [`FileOps::is_unix_socket`] exists.
    fn containment(&self) -> FdContainment;
```

**The 13 impls and their answers.** Every `impl FileOps` in the tree, its file,
and the evidence for its answer. A one-line addition to each; the `Leaf` ones
are `Leaf` because a grep for a `FileRef`-typed field across the tree returns
exactly six sites (`fs/src/fileio/fdops.rs:948` — a local in
`fileio_install_file_ref_at`; `net/src/unix_socket/pair.rs:55,74`;
`ring/src/enter.rs:312`; `ring/src/opcode.rs:77`; `ring/src/ring_obj.rs:24`),
and only the last four are reachable from a description's backing.

### 4.2 Layer B — purge an ancillary queue the moment it becomes undeliverable

> **Review finding R1, accepted — revision 1's Layer B was a data-loss bug.**
> It purged **both** directions at the first close, justified by "`drain_ancillary`
> requires a live `Connected` slot on the receiving side". Re-reading the close
> path, that justification is false for one of the two directions.
> `unix_close` removes only the *closing* slot (`mod.rs:778`) and marks the peer
> `peer_closed = true` (`mod.rs:784-791`); the peer's slot stays
> `SlotState::Connected` and stays in the table. `drain_ancillary` matches
> `SlotState::Connected { pair, side, .. }` with no `peer_closed` test
> (`mod.rs:658-663`), and `PairTable::release` returns `None` at refcount 1
> (`pair.rs:229-234`), so the pair and both queues are still reachable. A
> surviving peer therefore **can and does** still receive what the closing side
> queued — that is ordinary POSIX behaviour (data and fds written before a close
> remain readable), and `unix_recv`'s EOF arm (`mod.rs:333-336`) only reports
> EOF once the FIFO is empty, for exactly that reason.
>
> Purging that direction would have deleted deliverable descriptors. Layer B is
> narrowed accordingly.

**The corrected rule.** At `unix_close(X)`, purge exactly the queue whose
**receiver is X**, and nothing else:

- `anc` *toward* X — X's `recv_anc(side)` (`pair.rs:177-182`) — becomes
  permanently undrainable the instant X's slot is removed, because
  `drain_ancillary` resolves the queue through the *receiver's* slot
  (`mod.rs:658-666` calls `pair_ref.recv_anc(side)` on the slot it just
  resolved) and X no longer has one. **Purge.**
- `anc` *from* X — X's `send_anc(side)` (`pair.rs:169-174`) — is drained by the
  surviving peer, which is still `Connected`. **Leave.** It is released by the
  peer's own close, through this same rule, or by the peer draining it first.

So the second close still frees the remainder, but neither close can strand a
deliverable descriptor. The retention window shrinks from "until both endpoints
close" to "until the receiving endpoint closes", which is the bound POSIX
semantics permit and no smaller.

> **Review finding R4, accepted — the concatenation allocated under the lock.**
> Revision 1 concatenated the two queues into one `KVec<InFlightFile>` and
> claimed a reservation at pair creation covered it. It does not:
> `AncillaryQueue::drain` is `core::mem::replace(&mut self.entries, KVec::new())`
> (`pair.rs:103-105`), so the queue's reserved capacity **leaves with the drain**
> and the next `push` reallocates. Worse, `out.push(e)` on a saturated `out`
> calls `KVec::push` → `try_reserve` (`slopos-ostd/src/mm/heap.rs:502-506`) — an
> allocation while `UNIX_STATE` is held, which is a `LOCK_LEVEL_REGISTRY` →
> `LOCK_LEVEL_ALLOCATOR` edge the whole module is written to avoid
> (`mod.rs:765-768`, `pair.rs:38-41`).
>
> The purge therefore moves **queue headers**, not entries. `AncillaryQueue` is
> one `KVec` header (24 B); `mem::replace`-ing it is a memcpy of 24 bytes and
> allocates nothing.

`net/src/unix_socket/pair.rs` gains:

```rust
impl ConnectionPair {
    /// Take the queue whose **receiver** is `side`, leaving the other alone.
    ///
    /// Called when `side`'s endpoint closes. `drain_ancillary` resolves a queue
    /// through the receiving slot (`mod.rs:658-663`), and that slot is gone, so
    /// from this instant nothing can deliver these. The opposite direction is
    /// deliberately untouched: its receiver is the surviving peer, whose slot
    /// stays `Connected`, so those entries are still deliverable.
    ///
    /// Returns the whole `AncillaryQueue` rather than its entries: moving the
    /// header is a 24-byte `mem::replace` and allocates nothing, which is what
    /// makes this callable under `UNIX_STATE`.
    #[must_use]
    pub(super) fn take_recv_anc(&mut self, side: PairSide) -> AncillaryQueue {
        core::mem::replace(self.recv_anc(side), AncillaryQueue::empty())
    }
}

impl AncillaryQueue {
    /// A queue with no storage. Only ever installed as the residue of
    /// [`ConnectionPair::take_recv_anc`], on a pair whose receiving endpoint is
    /// gone — so nothing will push to it again, and the lost reservation is
    /// not a regression on any live path.
    pub(super) const fn empty() -> Self {
        Self { entries: KVec::new() }
    }
}
```

`KVec::new()` is `const` and allocation-free (`heap.rs:488-492`), so
`AncillaryQueue::empty()` is `const` too.

`net/src/unix_socket/mod.rs`, `unix_close` (:754-830). The existing structure
already carries a post-lock `freed_pairs: KVec<ConnectionPair>` (:769-772) and
drops it after the critical section (:812). Add a sibling with the same shape:

```rust

    // after it. One entry per pair this close can orphan a queue from — one
    // for the connected case, up to MAX_BACKLOG for the listener case — so the
    // reservation matches `freed_pairs`' and collection never allocates under
    // the state lock.
    let mut orphaned: KVec<pair::AncillaryQueue> =
        match KVec::with_capacity(MAX_BACKLOG + 1) {
            Ok(v) => v,
            Err(_) => return Errno::ENOMEM.raw(),
        };
```

and in the `SlotState::Connected` arm (:783-796). Note it needs `side`, which
the existing pattern discards — `SlotState::Connected { pair, peer, .. }` becomes
`{ pair, side, peer, .. }`:

```rust

                if let Some(p) = pairs.get_mut(pair) {
                    let _ = orphaned.push(p.take_recv_anc(side));
                }
                // ... existing peer_closed marking, wake_peer, release ...
            }
```

`orphaned.push` cannot fail: capacity is `MAX_BACKLOG + 1` and this arm pushes
once. The `let _ =` is there because `KVec::push` is `#[must_use]`-shaped
fallible, not because failure is tolerated — a failure here would drop the queue
*under the lock*, which is why the reservation is proved rather than assumed.

The same one line goes into `close_listener_backlog` (:714-749), which already
receives `pairs: &mut PairTable` and already collects into `freed_pairs`. Its
backlog entries are all side **B** (`unix_connect` inserts `h_b` into the
listener's backlog, `mod.rs:262-268`), so the call is
`p.take_recv_anc(PairSide::B)` on each `b_pair` — taking what side A queued
toward the never-accepted embryo, which no `accept` will ever produce a slot
for. The backlog is at most `MAX_BACKLOG` entries (`slot.rs:12`, enforced at
`mod.rs:216-218`), so `MAX_BACKLOG + 1` covers listener and connected cases
with one spare. The embryo case is Linux's 2024-05-21 *"garbage collection of
embryos"* fix site, reached here structurally rather than by a walk.

`drop(orphaned)` goes immediately after `drop(freed_pairs)` at :812 — outside
the lock, before any `BUS.publish`. That drop runs each `InFlightFile`'s
destructor: the `Charge<CustodyAxis>` refunds (`pair.rs:57`), the
`InflightSlot` (§4.3 C1) decrements, and the `LeafFileRef` closes, which may
re-enter `unix_close` — legal exactly because the lock is released.

**Stack-frame note.** `unix_close`'s frame is already near the gate, which is why
`close_listener_backlog` carries `#[inline(never)]` (`mod.rs:713`). The new
`orphaned` vec is one `KVec` header (24 B) on the frame, its storage on the heap;
`take_recv_anc` returns a 24-byte `AncillaryQueue` by value, so no large rvalue
materialises. `close_listener_backlog` gains one parameter and no locals. If
`check_stack_sizes.sh` still moves, the fix is to split further — see §7.

**Semantic consequence, stated plainly:** a socket that closes without draining
loses the descriptors queued *to it*, at its own close rather than at its peer's.
Nothing observable changes for the peer, which can still receive everything it
was sent and everything it queued outward until it too closes. This matches the
documented `AF_UNIX` behaviour that descriptors queued to a socket are released
when that socket is destroyed.

### 4.3 Layer C — bound, count, expose

> **Review findings R2 and R3, both accepted — revision 1's counter did not
> compile and its ordering claim was wrong.**
>
> **R2.** Revision 1 said "decremented in `InFlightFile::drop`". Adding `Drop`
> to `InFlightFile` breaks `drain_ancillary`, which destructures the struct to
> move the reference out: `out_files.push(entry.file)` (`mod.rs:673`). Rust
> forbids moving a field out of a type that implements `Drop` (E0509). The same
> objection applies to `Charge<CustodyAxis>`, which is why *it* is a field with
> its own destructor rather than logic in an outer `Drop` — `pair.rs:54-58`.
> The counter follows that existing pattern exactly.
>
> **R3.** Revision 1 called the increments "relaxed … guarded by the
> `UNIX_STATE` critical section they occur in, so the value is exact". The
> increments are, but the **decrements are not**: an entry's destructor runs
> when the drained/purged `KVec` drops, which §4.2 and `drain_ancillary`
> (`mod.rs:670-677`) both deliberately do *outside* the lock. So the counter is
> genuinely concurrent and gets a real ordering.

**C1. System-wide in-flight ceiling**, as a linear slot token.
`net/src/unix_socket/pair.rs`:

```rust
use core::sync::atomic::{AtomicU32, Ordering};

/// System-wide in-flight SCM_RIGHTS descriptors.
///
/// Per-account `Custody` bounds one account (64, `abi/src/quota.rs:163`); this
/// bounds the sum, so N cooperating accounts cannot pin N x 64 descriptions
/// between them.
static UNIX_INFLIGHT_TOTAL: AtomicU32 = AtomicU32::new(0);

/// The storage bound is MAX_UNIX_PAIRS(64) x 2 directions x MAX_INFLIGHT_FDS(8)
/// = 1024. The ceiling sits at half of it so exhaustion is a refusal with
/// headroom, not a wall at the structural limit.
pub(super) const UNIX_INFLIGHT_MAX: u32 = 512;

/// One unit of the global in-flight count, released by its own destructor.
///
/// A field with a `Drop`, not logic in `InFlightFile::drop`: `drain_ancillary`
/// moves `entry.file` out of `InFlightFile` (`mod.rs:673`), which a `Drop` impl
/// on the outer struct would forbid (E0509). Same reason
/// `Charge<CustodyAxis>` is shaped this way.
pub(super) struct InflightSlot;

impl InflightSlot {
    /// `None` when the global ceiling is reached. `AcqRel` on success so the
    /// entry's construction is visible to whichever CPU later drops it, and
    /// the failure ordering is `Acquire` for the reload.
    fn try_take() -> Option<Self> {
        let mut cur = UNIX_INFLIGHT_TOTAL.load(Ordering::Acquire);
        loop {
            if cur >= UNIX_INFLIGHT_MAX {
                return None;
            }
            match UNIX_INFLIGHT_TOTAL.compare_exchange_weak(
                cur,
                cur + 1,
                Ordering::AcqRel,
                Ordering::Acquire,
            ) {
                Ok(_) => return Some(Self),
                Err(observed) => cur = observed,
            }
        }
    }
}

impl Drop for InflightSlot {
    /// One `fetch_sub` on `.bss` — no lock, no allocation — so this is legal
    /// from the off-lock purge drop and from a dying task's own unwind. Cannot
    /// underflow: the only minter is `try_take`, and the token is neither
    /// `Clone` nor constructible elsewhere in the module.
    fn drop(&mut self) {
        UNIX_INFLIGHT_TOTAL.fetch_sub(1, Ordering::AcqRel);
    }
}
```

`InFlightFile` carries it as a third field:

The existing alias dance (`pair.rs:81-92`) is unchanged: `KVec::push` consumes

**Reporting the refusal.** Today `unix_sendmsg` swallows a refused push
(`mod.rs:534-541`: `if let Err(refused) = anc.push(..) { drop(refused); }`) — it
drops the file and still returns the byte count, because the per-direction cap

## 5. Invariants, locking, and interaction with existing subsystems

### 5.1 Invariants established

- **U-1 (leaf-only ancillary).** Every `InFlightFile` holds a `LeafFileRef`.
  Since a `LeafFileRef` names a description that owns no `FileRef`, the
  "description owns description" relation restricted to ancillary queues has
  depth exactly 1 and therefore no cycle. Enforced by the type, not by a check.
- **U-2 (no undeliverable retention), as corrected.** *Revision 1 stated this as
  "from the instant either endpoint closes, that pair's queues are empty", which
  is both false as a description of the fix and wrong as a goal — see §4.2 R1.*
  The real invariant:

  > A queue whose **receiving** endpoint has left the slot table is empty.

  Enforced by Layer B at the two — and only two — places a slot leaves the
  table while `Connected`: `unix_close`'s `Connected` arm (`mod.rs:783`) and
  `close_listener_backlog`'s `slots.remove` (`mod.rs:716-724`). Contrapositive:
  a non-empty queue has a live receiving slot, so `drain_ancillary` can still
  resolve and empty it. Retention is bounded by *one* endpoint's lifetime, not
  two.
- **U-3 (bounded in-flight).** `UNIX_INFLIGHT_TOTAL <= UNIX_INFLIGHT_MAX`
  always, and per account `Custody <= 64` (`abi/src/quota.rs:163`). The first
  holds because `InflightSlot::try_take`'s compare-exchange is the only
  increment and it tests the bound inside the loop, so a lost race retries
  against the observed value rather than overshooting.
- **U-4 (drop discipline, pre-existing, preserved).** No `FileRef` is dropped,
  and no allocation is attempted, while `UNIX_STATE` is held. Layer B adds a
  second pre-reserved off-lock collection vec beside `freed_pairs` and moves
  only 24-byte queue headers under the lock; it adds no drop site and no
  allocation site inside the critical section (§4.2, R4).
- **U-5 (containment is stated).** Every `FileOps` impl answers `containment()`,
  and the method has no default body, so a new impl does not compile until it
  does. There is one statement of containment per description — the
  `file_kind_containment` free function and its `debug_assert` cross-check are
  **removed** from the design (§4.1, R6), because two statements of the same
  fact is what created the need to police them against each other.

### 5.2 Locking

No new lock, no new lock class, no new lock-order edge. All state added is:

- `UNIX_INFLIGHT_TOTAL: AtomicU32` — global `.bss`. *Revision 1's ordering claim
  ("relaxed increments guarded by the `UNIX_STATE` critical section, so the
  value is exact") was wrong and is retracted (R3).* Increments do happen under
  `UNIX_STATE`, from `AncillaryQueue::push`. **Decrements do not**: an
  `InflightSlot` is dropped when the vec holding its `InFlightFile` drops, and
  both such sites are deliberately off-lock — `drain_ancillary`'s post-lock loop
  (`mod.rs:670-677`) and `unix_close`'s `drop(orphaned)` (§4.2). So the counter
  is concurrent, and it uses `compare_exchange_weak(AcqRel, Acquire)` to
  increment and `fetch_sub(AcqRel)` to decrement. The read in `unix_stats` is
  `Relaxed` and documented as advisory.
- `orphaned: KVec<pair::AncillaryQueue>` — a local, on the closing task's stack
  frame, one 24-byte header per entry.

**Global vs per-CPU:** the counter is global rather than per-CPU because it is a
ceiling, not a statistic; a per-CPU sum would have to be reconciled on every push
to answer "am I over", which is more expensive than the one CAS it replaces.
`AncillaryQueue` stays inside `ConnectionPair` under `UNIX_STATE` — there is no
per-CPU shard to be had, because the pair is inherently shared between two tasks
that may run anywhere.

`UNIX_STATE` remains a single `SpinLock` at `LOCK_LEVEL_REGISTRY`
(`mod.rs:56-59`, `lock_class!("UNIX_STATE", LOCK_LEVEL_REGISTRY)`). **No new
`lock_class!` is introduced anywhere in this fix** — that is the falsifiable
claim behind "class counts unchanged" in §7, and `check_lockdep_headroom.sh`'s
class-count arm is what checks it: class counts are deterministic, so a moved
class count means a lock was added that this document does not describe.

Because the design has **no collector**, there is no worker that must take
`UNIX_STATE` while holding anything else, which is precisely the lock-order
hazard Linux's `unix_gc_lock` carries (and why its 2024 rewrite needed
`U_RECVQ_LOCK_EMBRYO` nesting classes).

### 5.3 TLB shootdown

Untouched. The fix frees no page tables and unmaps nothing. Freed FIFO pages go
back through the existing `KVecDeque` drop path, and the buddy allocator's reuse
path already performs synchronous cross-CPU TLB drains (AGENTS.md, I3). Layer B
makes those frees happen *earlier*, on the closing task's own stack, with IRQs
enabled and no lock held — which is the context that discipline requires.

### 5.4 Quota accounting

- `Custody` charges and refunds are unchanged in shape. Layer B makes the refund
  for the *inbound* direction happen at the receiving endpoint's close rather
  than at the pair's release, so measured `Custody` peaks can only fall; the
  outbound direction is unchanged in timing (§4.2, R1). Refunds still travel
  with the entry (`pair.rs:54-58`), so the "exactly once, in the same move"
  property holds — and adding `InflightSlot` beside the `Charge` preserves it,
  because both are fields whose destructors run with the entry rather than
  logic in an outer `Drop` (§4.3, R2).
- `check_charge_linearity.sh` is unaffected: no `mem::forget`, no
  `Option<Charge<_>>`, no `.take()` on a charge field, no fn returning a
  `Charge` by value, no `Clone`/`Copy` derive near a charge-bearing field — the
  five checks that gate names (`scripts/check_charge_linearity.sh:21-31`).
  `InFlightFile` gains a field and keeps its lack of a `Drop` impl, which is
  what lets `drain_ancillary` keep moving `file` out.
- `ObjectRow` (per AF_UNIX endpoint, `unix_socket_file_ops.rs:39`) is the axis a
  leaked slot never refunds today; Layer A + B make that unreachable, so
  `ObjectRow` peaks become bounded by live sockets again.
- New axis: **none.** `UNIX_INFLIGHT_TOTAL` is deliberately not a quota axis —
  it has no account and no parent chain, so modelling it as one would put a
  fictional row in the arena.

### 5.5 Authority model

`syscall_sendmsg` keeps `cap(NoneFd)`; nothing here reaches a power primitive, so
`check_authority_reachability.sh` sees no new edge. The refusal is a *reduction*
in what an unprivileged caller can cause the kernel to allocate.

### 5.6 Task ownership (I1–I8)

No `Task`, `KArc<Task>` or `TaskRef` is touched. The blocking loop in
`unix_sendmsg` (`mod.rs:562-590`) keeps `files` on the caller's stack across the
park — its own comment says so (`mod.rs:565`) — which is I8-compatible: a
`wait_event` error unwinds by *returning* `EINTR` (`mod.rs:589-591`), and the
caller's frame drops the `LeafFileRef`s on its own stack. The wait predicate
(`mod.rs:566-588`) is unchanged and stays pure, so
`check_wait_predicate_purity.sh` sees nothing new.

| Situation | Result |

## 8. Tests that pin the fix

Each is stated with the exact failure mode it catches, and with the **observable**
it asserts on. Kernel-side tests join the existing `unix_scm_rights` suite in
`core/src/syscall/tests.rs:5497-5886`, which already has the fixtures they need:
`unix_create_connected_pair_raw()` (:5499-5539, builds a bound/listening/accepted
pair of raw `SocketHandle`s) and `SyscallFixture` + `create_test_user_task()` for
an fd table. Adding them there rather than in a new `net/src/tests/` module is a
correction to revision 1: the tests need `FdTable`, `memfd_create` and
`ring_setup`, none of which `net/` can reach.

> **Review finding R7, accepted.** Revision 1's test 5 asserted `memfd_size == 0`
> after the receiver's close. A closed description exposes no size — there is no
> fd left to `fstat`, and `memfd_size` is not an accessor the tree has. The
> observable that *does* work is already used by the neighbouring test:
> `test_scm_rights_tty_balanced` (`tests.rs:4090-4135`) holds an independent
> probe reference and asserts on `KArc::strong_count`. `FileRef` exposes the
> same thing as `description_strong_count` (`fs/src/fileio/mod.rs:209-212`),
> documented "for lifetime assertions in tests". Every retention test below
> asserts on that.

1. **`test_unix_scm_self_reference_frees_the_slot`** — *the load-bearing test.*
   Record `unix_stats()`; run the §1.7 repro (connect pair, `sendmsg(fd_a,
   [fd_a])`, close both); assert live slots and live pairs return to baseline.
   **Fails today:** the send succeeds and both counts stay above baseline
   forever. Catches: the exact reported leak.
2. **`test_unix_scm_refuses_unix_socket_fd`** — install an AF_UNIX endpoint as an
   fd, `sendmsg` naming it, assert `EOPNOTSUPP` and that
   `description_strong_count` of an independently held alias is unchanged after
   the call. **Fails today:** returns the byte count and the count rises.
   Catches: regression of `UnixSocketFileOps::containment`, and a refusal path
   that leaks the alias.
3. **`test_unix_scm_refuses_ring_fd`** — same with a `FileKind::Ring` fd from
   `ring_setup`. **Fails today:** succeeds. Catches: the io_uring-shaped cycle,
   which the minimal patch would have left open (§3.2).
4. **`test_unix_scm_permits_inet_socket_fd`** — *the R6 rebuttal, pinned.*
   `sendmsg` naming an **AF_INET** fd still succeeds and still delivers.
   **Passes today and must keep passing.** Catches: a future refactor that
   re-keys containment on `FileKind` and silently breaks TCP fd passing — the
   regression revision 1 would have shipped.
5. **`test_unix_scm_two_socket_cycle_frees_both_slots`** — the classical cycle:
   two pairs, cross-send each socket's fd over the other, close all four fds,
   assert baseline. **Fails today.** Catches: a Layer A hole that admits a
   depth-2 cycle while blocking the self-loop (the Zircon rule alone would).
6. **`test_unix_anc_purged_when_receiver_closes`** — send a memfd (a legal leaf)
   from A to B while holding an independent `FileRef` probe on it; record
   `probe.description_strong_count()`; close **B** (the receiver) without
   draining, leaving A open; assert the count returns to baseline.
   **Fails today:** the count stays one high until A also closes. Catches:
   Layer B's connected arm — the cycle-independent retention bug.
7. **`test_unix_anc_survives_sender_close`** — *the R1 regression guard, and the
   test revision 1's design would have failed.* Send a memfd from A to B, close
   **A** (the sender), then `unix_recvmsg` on B and assert the fd **is still
   delivered**. **Passes today and must keep passing** — `unix_close` marks the
   peer `peer_closed` but leaves its slot `Connected` (`mod.rs:783-796`) and
   `drain_ancillary` does not test `peer_closed` (`mod.rs:658-663`). Catches: a
   Layer B that purges both directions.
8. **`test_unix_anc_purged_on_unaccepted_backlog`** — A connects to a listener,
   sends a memfd toward the never-accepted embryo, then the listener closes.
   Assert the probe count returns to baseline. **Fails today.** Catches: Layer
   B's `close_listener_backlog` arm — the case Linux needed a dedicated 2024
   fix for.
9. **`test_unix_inflight_global_ceiling_denies`** — saturate `UNIX_INFLIGHT_MAX`
   across several pairs, assert the next send returns `ENFILE`, that
   `unix_stats().2 <= UNIX_INFLIGHT_MAX`, that the refused files are **still in
   the caller's vec** (not silently dropped), and that draining restores
   headroom. **Fails today:** no ceiling exists. Catches: U-3, and the
   silent-drop arm the ceiling replaces (§4.3 C1).
10. **`test_unix_scm_custody_refunded_at_receiver_close`** — `Custody` for the

    Layer B implementation that purges the queue but loses the entries' charges
    — e.g. one that drains entries rather than moving the queue header.
11. **`test_unix_inflight_slot_released_on_every_exit`** — drive one descriptor

13. **`test_leaf_file_ref_rejects_container`** (in `fs/src/tests.rs`, beside the

## 10. Residual risk — what this does **not** close

1. ~~**Containment is per-kind, not per-instance.**~~ **Withdrawn** (review
   finding R6). It was an artefact of revision 1 keying the predicate on
   `FileKind`. Containment is a `FileOps` method, and `FileOps` is already
   per-family (`SOCKET_FILE_OPS` vs `UNIX_SOCKET_FILE_OPS`), so AF_INET answers
   `Leaf` and keeps passing over SCM_RIGHTS. There is **no POSIX deviation for
   AF_INET**, and §8.4 pins that. The remaining deviation is the intended one:
   passing an AF_UNIX socket or a ring fd is refused with `EOPNOTSUPP`, which
   *is* a documented deviation and does belong in the syscall's ABI notes.
2. **`FileOps::containment()` is an assertion, not a proof.** A new subsystem
   that stores a `FileRef` and answers `Leaf` reintroduces the class. Revision 1
   proposed a `debug_assert` cross-check against a second per-kind statement;
   that is deleted with the function it checked (§4.1), and it would not have
   caught this case anyway — it caught *disagreement between two statements*,
   never a consistent lie. What actually narrows it is that the answer sits on
   the trait with no default body, so writing a new `FileOps` impl forces the
   question at the moment the `FileRef` field is being added. A future gate
   could scan for `FileRef` / `LeafFileRef` fields in types reachable from a
   `FileBacking` impl and require `Container`; that is real work and is **not**
   proposed here.
3. **Other kernel containers of `FileRef` are not swept.** `Ring::inflight` holds
   `FileRef`s (`ring/src/enter.rs:312`) and is reclaimed by `RingBacking::drop`
   (`ring/src/file_ops.rs:32`). A ring holding a `FileRef` to a socket is fine
   *because the socket can no longer hold a ref to the ring*. If a future path
   installs a `FileRef` into a ring from somewhere other than the owner's fd
   table, that path needs the same choke point.
4. **`MAX_UNIX_SOCKETS` remains a hard system-wide 128** with no per-account
   share. A process can still consume most of the table with plain sockets and
   no fd-passing at all — a *bounded, self-refunding* denial, unlike the leak,
   but a denial. The `ObjectRow` axis (default 512) does not bind below 128.
   Separate finding; out of scope.
5. **The 2 MiB FIFO pin is untouched.** 64 pairs × 2 × 16 KiB is reachable by
   legitimate use and is not reduced here.
6. **`MSG_PEEK` does not exist in this tree**, which is why the seqcount race
   Linux fixed in 2026-03 is unreachable. If `MSG_PEEK` is added, the Layer B
   purge point must be re-examined: a peeking receiver would hold a reference the
   purge does not see.
7. **`unix_close` can already fail with `ENOMEM` from a `Drop`**, where the
   return value is discarded (`unix_socket_file_ops.rs:30-34`). Layer B adds a
   second `KVec::with_capacity(MAX_BACKLOG + 1)` on that path, widening an
   existing window in which a close under memory pressure silently does not
   close. **The implementation should close this rather than widen it**, and the
   fix is small and local: make `freed_pairs` and `orphaned` a single
   pre-reserved `KVec<(ConnectionPair-or-AncillaryQueue)>`, or hoist both into
   one `struct CloseHarvest` reserved once. Either way it is one allocation on
   the close path instead of today's one plus this fix's one. Recorded here
   rather than folded into §4.2 because it changes `freed_pairs`, which is
   pre-existing code this finding does not otherwise touch — but it should land
   in the same commit.
8. **Retention is still one endpoint's lifetime, not zero.** Layer B, correctly
   narrowed (§4.2, R1), bounds retention by the *receiving* endpoint's life. A
   receiver that stays open forever and never drains still pins what was sent to
   it — bounded by `MAX_INFLIGHT_FDS` per direction, by per-account `Custody`,
   and now by `UNIX_INFLIGHT_MAX` globally, so it is a *bounded* pin rather than
   a leak. That is the correct semantics (the descriptors are genuinely still
   deliverable) and not a defect, but it is worth stating that the fix does not
   make in-flight retention zero.
9. **Two defects found while answering this review, neither of which is this
   finding.** Recorded rather than fixed here:
   - `AncillaryQueue::drain` (`pair.rs:103-105`) is
     `mem::replace(.., KVec::new())`, so the queue's `MAX_INFLIGHT_FDS`
     reservation — taken at `AncillaryQueue::new` (`pair.rs:61-65`) precisely so
     commit-path pushes never allocate under the lock (`pair.rs:38-41`) — is
     **lost on the first drain**, and every subsequent `push` on that queue can
     allocate while `UNIX_STATE` is held. Layer B routes around it (it moves
     headers, never pushes entries), but the underlying path remains. Fix:
     `drain` should swap in a freshly reserved queue, or the pushes should
     re-reserve off-lock. **Its own finding.**
   - `abi/src/quota.rs:160-162` says the `Custody` structural bound is
     "8 fds x 2 directions x **16 pairs**", and `pair.rs:48-50` repeats it.
     `MAX_UNIX_PAIRS` is `MAX_UNIX_SOCKETS / 2` = **64** (`pair.rs:24`,
