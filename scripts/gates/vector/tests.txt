# check_kernel_softfloat allowlist — variant: tests
#
# Instructions touching XCR0-managed state (XMM/YMM/ZMM, x87, MMX, and the
# xsave/xrstor pair) that are permitted, each capped at its measured
# occurrence count in the named symbol.
#
#     scripts/check_kernel_softfloat.sh --variant tests --emit-allowlist builddir/kernel-tests.elf
#
# Every entry must match at least one hit. A dead entry fails the gate.

# Liveness floors — see the dev allowlist. Measured 2026-07-31: 44585 returns
# / 44970 symbols.
min-returns 30000
min-symbols 30000

# The kernel/tests image registers thousands of tests.
expect-test-registry many

# <max-hits> <TAB> <class-or-mnemonic> <TAB> <glob over the symbol>

# The xsave/AVX conformance helpers: each routes its payload through memory
# with explicitly named registers, saves and restores around its own use, and
# runs with interrupts disabled — never in a fault path.
#
# This replaces the whole-binary exemption the tests kernel used to carry.
# Those helpers' own soundness argument is that the kernel never touches the
# vector register file between their two halves — a claim about *this*
# binary, left unchecked by exempting the whole image.
78	vec	*slopos_ostd12test_support9cpu_state*
2	xsave	*slopos_ostd12test_support9cpu_state*

# The scheduler's own FPU save/restore — the sanctioned save/restore the rest
# of the gate exists to protect. Allowlisted rather than excluded so the
# budget still catches a second, unreviewed xrstor appearing elsewhere.
3	xsave	*slopos_ostd4task3fpu*

# The restore half of that pair, in its own `global_asm!` symbol band so a #GP
# from a user-supplied XSAVE image lands on a fault tail instead of killing the
# machine. One instruction is the whole point of the band: the RIP range the
# #GP handler matches has to contain nothing else.
1	xrstor64	__ostd_fpu_xrstor*

# One `fxsave64` at boot, reading this CPU's MXCSR_MASK out of the legacy
# region — the value is published by no other instruction and by no CPUID leaf,
# and validating a user-supplied MXCSR needs it. FXSAVE reads the register file
# and writes memory, so it disturbs nothing; it runs once on the BSP, before
# any user task exists.
1	fxsave64	*detect_mxcsr_feature_mask*

# The one-time x87 init in the assembly entry trampoline
# (boot/limine_entry.s), immediately after the CR0/CR4 setup and before any
# Rust runs. Not a fault path: nothing has user state to clobber yet.
#
# The one-time x87 init in the assembly entry trampoline (boot/limine_entry.s),
# immediately after the CR0/CR4 setup and before any Rust runs. Not a fault
# path: nothing has user state to clobber yet.
#
# The glob spans the aliases the site can be reported under. `_start`,
# `_text_start` and `_kernel_start` can all sit at the head of .text,
# llvm-objdump prints one header per address, and which alias it picks follows
# the image layout — a property of the link, not of the build variant, so
# pinning one name breaks whenever a different toolchain lays the image out
# differently. The literal `fninit` and the budget of one are what keep the
# exemption exact: a second x87 instruction in that symbol still fails.
1	fninit	_*start
