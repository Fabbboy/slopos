# check_kernel_softfloat allowlist — variant: release
#
# Instructions touching XCR0-managed state (XMM/YMM/ZMM, x87, MMX, and the
# xsave/xrstor pair) that are permitted, each capped at its measured
# occurrence count in the named symbol.
#
#     scripts/check_kernel_softfloat.sh --variant release --emit-allowlist builddir/kernel-release.elf
#
# Every entry must match at least one hit. A dead entry fails the gate.
#
# This file shares no entry with the dev allowlist, and the two must never be
# merged: at opt-level 3 the `slopos_ostd::task::fpu` wrappers are inlined
# away entirely and the same instructions are attributed to their *callers*.

# Liveness floors. Measured 2026-07-31: release 3856 returns / 4068 symbols
# against dev's 31098 / 31472 — optimisation inlines away roughly seven
# eighths of the functions, which is also why `--variant dev` against a
# release ELF fails rather than passing on a list that happens to fit.
min-returns 1200
min-symbols 1200

expect-test-registry few

# <max-hits> <TAB> <class-or-mnemonic> <TAB> <glob over the symbol>

# The sanctioned FPU save, one entry per site the wrapper inlines into.
# Allowlisted rather than excluded, so a fifth site appearing is something
# somebody has to look at. The restore half is not here: it lives in a symbol
# band of its own (below) and therefore inlines nowhere.
2	xsave	*slopos_core7syscall6signal20save_fpu_to_sigframe*
2	xsave	*slopos_sched4task14task_lifecycle9task_fork*
2	xsave	*slopos_sched4task14task_lifecycle10task_clone*
4	xsave	*slopos_sched9scheduler17prepare_switch_to*

# The restore half, in its own `global_asm!` symbol band so a #GP from a
# user-supplied XSAVE image lands on a fault tail instead of killing the
# machine. One instruction is the whole point of the band: the RIP range the
# #GP handler matches has to contain nothing else. Being hand-written asm, this
# is the one entry that reads the same in every variant.
1	xrstor64	__ostd_fpu_xrstor*

# One `fxsave64` at boot, reading this CPU's MXCSR_MASK out of the legacy
# region — the value is published by no other instruction and by no CPUID leaf,
# and validating a user-supplied MXCSR needs it. FXSAVE reads the register file
# and writes memory, so it disturbs nothing; it runs once on the BSP, before
# any user task exists.
1	fxsave64	*detect_mxcsr_feature_mask*

# The one-time x87 init in the assembly entry trampoline (boot/limine_entry.s),
# immediately after the CR0/CR4 setup and before any Rust runs. Not a fault
# path: nothing has user state to clobber yet.
#
# The glob spans the aliases the site can be reported under. `_start`,
# `_text_start` and `_kernel_start` can all sit at the head of .text,
# llvm-objdump prints one header per address, and which alias it picks follows
# the image layout — a property of the link, not of the build variant, so
# pinning one name breaks whenever a different toolchain lays the image out
# differently. The literal `fninit` and the budget of one are what keep the
# exemption exact: a second x87 instruction in that symbol still fails.
1	fninit	_*start
