# check_lockdep_headroom gate data — variant: tests
#
# The lock-order validator must be ACTIVE at every phase it reports, must
# report no violation, and must keep every pool clear of its ceiling. An entry
# records what a pool *is*, not that the value is acceptable.
#
#     scripts/check_lockdep_headroom.sh --variant tests --emit-allowlist
#
# Every require-phase and every cap must be matched by a LOCKDEP[...] line: a
# cap matching nothing is a dead entry and fails the gate, because a phase that
# stopped reporting looks exactly like a phase that passed. Raise a cap only
# with a fresh --emit-allowlist in the same commit, and say in the message what
# added the locks.
#

# `tty_table_init`, which registers TTY_WRITE_LOCKS eagerly (+1 boot class, +1
# boot edge for the declared pair) instead of on its first acquire, and the

#
# Re-measured 2026-08-09 for the descriptor-table isolation test. Both test
# phases gain exactly one class, KERNEL_FILE_TABLE. The test asserts that a

# Re-measured over 4 runs for `waitpid(-1)`. Both test phases gain exactly one

# Classes must be well clear of the pool before the validator would disable
# itself. 70% mirrors MAX_POOL_FILL_PCT in ktesting/src/zz_lockdep_tests.rs;
# the failure it catches is a new array-of-locks static landing without a class
