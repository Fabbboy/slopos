# check_lockdep_headroom gate data — variant: tests
#
# The lock-order validator must be ACTIVE at every phase it reports, must
# report no violation, and must keep every pool clear of its ceiling. An entry
# records what a pool *is*, not that the value is acceptable.
#
#     scripts/check_lockdep_headroom.sh --variant tests --emit-allowlist
#
# Every require-phase and every cap must be matched by a LOCKDEP[...] line: a
# cap matching nothing is a dead entry and fails the gate, because a phase that
# stopped reporting looks exactly like a phase that passed. Raise a cap only
# with a fresh --emit-allowlist in the same commit, and say in the message what
# added the locks.
#
# Measured 2026-08-02 over 8 consecutive runs of the tests ISO. Re-measured
# 2026-08-03 when RCU's callback-batch lock and the bottom-half tests' probe lock
# each added a class; the edge and chain caps below still bound the new measurement
# with room to spare and are left at their 8-run values.
#
# Re-measured 2026-08-07 over 3 runs: the TTY lock order is now declared at
# `tty_table_init`, which registers TTY_WRITE_LOCKS eagerly (+1 boot class, +1
# boot edge for the declared pair) instead of on its first acquire, and the
# vconsole input-injection hook a test-hooks build carries adds one class to
# both test phases. Edge and chain caps still bound the new measurement.
#
# Re-measured 2026-08-09 over 4 runs for the network-management change. Boot
# gains exactly five classes, one per new lock the kernel now takes:
# NET_IFACES (the interface table), NETMON (the monitor registry),
# evbus.netmon (the wait queues a monitor fd blocks on, one class for the
# whole array), UDP_PORT_LISTENERS (the kernel-side port table DHCP binds 68
# on) and DHCP_CLIENTS. The test phases add those plus the scratch tables and
# mock locks the new iface, netmon and DHCP tests declare. Only the class caps
# move: every edge and chain measurement still falls under the caps below, and
# they keep their earlier values.
#
# Re-measured 2026-08-09 for the per-socket wait-queue spine. The three
# AF_INET socket queue classes (evbus.socket_recv / _send / _accept) now
# register from the boot-allocated spine rather than the static array, so both
# test phases gain exactly three classes. The instance count went 64 -> 1024
# per axis but the CLASS count is what the validator tracks, and a class is
# per declaration site, not per instance — which is the whole point of
# declaration-site keying. Edge and chain counts are unchanged.
#
# Re-measured 2026-08-09 for the descriptor-table isolation test. Both test
# phases gain exactly one class, KERNEL_FILE_TABLE. The test asserts that a
# process owning no table never has descriptors installed into the kernel's,
# and reading that table to prove it is the only acquire of that lock anywhere
# in the tree — measured by disabling the probe, which returns both phases to
# 176/185. Boot is unchanged; edges and chains stay under their caps.
#
# Re-measured over 4 runs for `waitpid(-1)`. Both test phases gain exactly one
# class, evbus.any_child_exit — the wait-queue array a wait-any caller parks on,
# one class for the whole array as evbus.netmon is. Boot is unchanged at 70:
# nothing on the boot path waits for an unnamed child, so the queue is first
# acquired by the wait-any test. Edges (kernel 145-149, userland 177-184) and
# chains (kernel 338-341, userland 379-384) still fall under the caps below and
# keep their earlier values.

# Classes must be well clear of the pool before the validator would disable
# itself. 70% mirrors MAX_POOL_FILL_PCT in ktesting/src/zz_lockdep_tests.rs;
# the failure it catches is a new array-of-locks static landing without a class
# key, which adds classes by the hundred.
max-fill-pct 70

# Without a floor, "0 classes" satisfies every ceiling and a validator that
# stopped registering reports as maximally healthy — the hole `min-records`
# plugs in the stack-size gate. Mirrors MIN_CLASSES in zz_lockdep_tests.rs.
min-classes 32

require-phase boot
require-phase post-kernel-tests
require-phase post-userland-tests

# <phase> <TAB> <pool> <TAB> <cap>
#
# Class counts were identical in all 8 runs, so their caps are the measured
# value with no margin: a class is registered on the first acquire of a
# declaration site, and by the end of a phase every site the phase reaches has
# been reached. One extra class is a new lock, which is exactly what should
# require a deliberate bump.
boot	classes	71

#

# gave deferred work more contexts to run in: the same orderings are reached,
# but which of them a given run has observed by the end of the phase now varies
# more. The edge caps still bound the new measurement and keep their 8-run
# values.
